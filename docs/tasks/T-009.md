## Goal

Prove that a SIGKILL during writes leaves a recoverable database with no corruption.

## Why

D1 F-O08; docs/15 NFR-4. See [20-claude-mem-feature-matrix.md](../20-claude-mem-feature-matrix.md) and, where relevant,
[22-improve-the-numbers.md](../22-improve-the-numbers.md) or [23-memory-building.md](../23-memory-building.md).

## Files to touch

- `test/crash.test.mjs`

## Steps

1. Spawn a child that inserts rows in a tight loop inside transactions.
2. Kill it with SIGKILL after a random delay.
3. Reopen the database, run `PRAGMA integrity_check`, and assert the count is monotonic.

## Acceptance criteria

- [x] `integrity_check` returns `ok` in 20 runs.
- [x] No partially committed transaction is visible.
- [x] The test finishes in under 30 s.

## Validation command

```bash
bun test test/crash.test.mjs
```

Deviation, 2026-10-27: the writer uses a raw `bun:sqlite` child with WAL and `synchronous=NORMAL` (the same
durability settings the HubStore uses) so the assertion targets SQLite recovery directly. Each run kills after a
random 120-300 ms delay; a run reopens read-only and checks `PRAGMA integrity_check`, that every committed batch has
all 50 rows, and that batch ids are contiguous from 1.
