# T-001: Make README claims generated, not typed

Status: validated
Phase: P0
Depends on: none
Validated on: 2026-10-27
Evidence:

## Goal

Replace hand-typed numbers in README (test count, feature claims) with values produced by a script, and fail when they drift.

## Why

D1 F-P02; D5 section 24.3. See [20-claude-mem-feature-matrix.md](../20-claude-mem-feature-matrix.md) and, where relevant,
[22-improve-the-numbers.md](../22-improve-the-numbers.md) or [23-memory-building.md](../23-memory-building.md).

## Files to touch

- `README.md`
- `scripts/check-claims.mjs`
- `package.json`

## Steps

1. Run `bun test`, parse the pass/fail counts and the total.
2. Write `scripts/check-claims.mjs` that recomputes the counts and compares them with README markers between `<!-- claims:begin -->` and `<!-- claims:end -->`.
3. Replace the hardcoded '115 tests' with a generated block.
4. Add `check:claims` to package.json.

## Acceptance criteria

- [x] README contains no hand-typed test count.
- [x] The script exits 1 when a marker value differs from the measured value.
- [x] Exit 0 prints the measured values.

## Validation command

```bash
bun scripts/check-claims.mjs
```

Expected: claims ok: tests=<n> passed=<n> failed=0

## Evidence

```
$ bun scripts/check-claims.mjs
claims ok: tests=1218 passed=1218 failed=0; badges=8 real; typed counts=0
```

The README carries a generated block between `<!-- claims:begin -->` and `<!-- claims:end -->` (currently
`**1,218 tests pass** — 1,218 pass, 0 fail`). `scripts/check-claims.mjs --write` regenerates it; the default run
fails when the block differs from the measured counts, and `findTypedCounts` ignores that block so a generated number
is never mistaken for a hand-typed one.
