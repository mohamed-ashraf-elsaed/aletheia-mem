## Goal

The work list accepts query params the UI can use: `filter` (all, needs-you, shipped) with counts, `sort` (needs-you,
newest, most-progress) and `group` by agent/tool. The same params work on `GET /v1/work/requests`.

## What changed

- `proposeRequests` accepts `filter`, `sort` and `group`. `counts` gains `all`, `needsYou` and `shipped` (alongside the
  existing working / idle / waitingOnYou / total). `filter` keeps all / needs-you / shipped. `sort` orders by newest,
  needs-you first or most-progress first. `group` by `agent` or `tool` returns `groups` buckets keyed by the request's
  latest tool.
- Each request now carries `tool` (the tool of its latest session).
- `GET /v1/work/requests` passes the three query params through and echoes `filter`, `sort` and `group`.

- [x] Sort needs-you first and most-progress first.
