# T-138: Add a read-only Tools tab from doctor data

Status: validated
Phase: P6
Depends on: T-134
Validated on: 2026-10-26
Evidence: see below.

## Goal

The Tools tab shows installer status from `aletheia doctor` data. Per tool: installed, hooks present (and how many
are expected), last capture and spool size, with copy-ready commands. Read-only in this task; no install runs from
the browser.

## Why

`aletheia doctor` printed its checks in a terminal only, and the old Hub Tools page wrote config files from the
browser. Users need to see what is installed without a write path in a web page. Part A of the `feat/one-ui` work
order.

## Files to touch

- `public/tabs/tools.js` (new): per-tool cards, doctor checks table, copy buttons, activity panel.
- `src/hub/routes.mjs`: `GET /api/hub/doctor` (landed with T-134) returns the same checks `doctor` produces, plus
  per-tool hook counts, last capture and spool size.

## Acceptance criteria

- [x] Each tool shows installed, hooks present/expected, its hooks file, last capture and spool items/bytes.
- [x] The doctor checks are shown with ok/fail and detail.
- [x] Commands are shown and copyable.
- [x] There is no install, uninstall or connect action in the page.
