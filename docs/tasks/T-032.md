The worker writes a session and a project summary after extraction, and `aletheia summarize --scope session|project|entity` writes any of the three on demand. A generated session summary replaces the Stop hook's raw assistant paste in the same memory id, with a `summary.replace` audit row. Default search hides a summary once every fact it cites is superseded.

## Goal

Produce summaries that are additional retrieval keys and always carry the ids they came from.

## Why

D3 E15; D4 section 23.5.9; D1 F-M03. See [20-claude-mem-feature-matrix.md](../20-claude-mem-feature-matrix.md) and, where relevant,
[22-improve-the-numbers.md](../22-improve-the-numbers.md) or [23-memory-building.md](../23-memory-building.md).

## Steps

1. Generate a session summary with request/investigated/learned/completed/next steps.
2. Generate a weekly project summary of decisions and gotchas.
3. Store `source_ids` and refuse a summary without them.

## Acceptance criteria

- [ ] No summary exists without source ids.
- [ ] The footprint drops >= 40% with <= 1 point Recall@5 loss on the fixture.
- [ ] A summary never deletes its sources.
