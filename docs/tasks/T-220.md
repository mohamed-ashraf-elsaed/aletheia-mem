# T-220: Use rule strength, evidence and the decide flow in the Rules tab

Status: validated

## Goal

Show each rule suggestion's strength, how often it was seen and its dated quotes, and move Accept, Reject and Edit
onto the T-172 decide flow. Add the on/off toggle, rule replacement and the learning-run status to the same page.

## Files to touch

- `public/tabs/rules-views.js`
- `public/tabs/rules.js`
- `test/ui-rules-decide.test.mjs` (new)
- `test/ui-rules.test.mjs` (update)

## What changed

- A suggestion card shows `strength` (with an "estimated" link, because the bands are chosen, not measured),
  `timesSeen`, `latestAt`, the first two dated quotes and a disclosure for `moreQuotes`.
- Pending rows use Approve, Edit and Reject. Approve posts `{action: "approve"}`; Edit opens a dialog and posts
  `{action: "edit", text}`; Reject posts `{action: "reject"}`. Undo restores the suggestion, and for Approve or Edit
  it also turns the new rule off, as the old Accept Undo did.
- The rule card's on/off action posts `POST /api/hub/rules/:id/toggle` with `{enabled}`, still optimistic with Undo.
- A Replace action opens a dialog, posts `POST /api/hub/rules/:id/replace`, reports the new rule and reloads. The old
  rule is kept and marked replaced; there is no unreplace route, so no Undo is offered.
- A learning-run panel reads `GET /api/hub/rules/learning-run` and a "Run now" button posts to it, then shows the
  recorded `at`, `found`, `proposed` and `errors`.
- Editing a rule's text still uses `PATCH /api/hub/rules/:id`.

## Acceptance criteria

- [x] Strength, times seen, latest date and dated quotes are shown; more quotes are behind a disclosure.
- [x] Approve, Edit and Reject call the decide route; Undo restores and turns the created rule off.
- [x] Toggle uses `/toggle`; Replace uses `/replace` and says what it does.
- [x] The learning-run status is shown and can be run.
