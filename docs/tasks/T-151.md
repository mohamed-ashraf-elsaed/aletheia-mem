# T-151: Add an auto-start service (systemd user unit and launchd plist)

Status: validated
Phase: P3
Depends on: none
Validated on: 2026-10-26
Evidence: see the Validation section below.

## Goal

`aletheia service install|uninstall|status [--write]` writes a systemd USER unit on Linux and a launchd
plist on macOS, dry-run by default, with a backup and a manifest. Real start is NOT RUN BY AUTHOR.

## Why

A server that runs from a hook or a foreground terminal does not survive a reboot. A dependency-free
auto-start unit lets the user run the loopback hub as a service without adopting a second tool.

## Files to touch

- `src/service.mjs` (new): `servicePlan`, `serviceInstall`, `serviceUninstall`, `serviceStatus`.
- `bin/aletheia.mjs`: the `service` command.
- `test/service.test.mjs` (new): the validation test.
- `docs/manual-test.md`: the NOT RUN BY AUTHOR manual step.
- `docs/tasks/research-log.md`: the Apple launchd docs fetch.

## Steps

1. Fetch the Apple launchd docs for the plist keys and record the URL.
2. Write the failing test first, then the generator.
3. Run the validation command and paste the real output.

## Acceptance criteria

- [x] The Linux unit has `Restart=on-failure`, `Nice=10`, loopback-only env, and documented overridable
  `CPUQuota`/`MemoryMax` defaults.
- [x] The macOS plist uses the documented launchd keys and is labelled `from-docs-only`.
- [x] Windows says it is not supported.
- [x] Install is dry-run by default, backed up, idempotent and manifests; uninstall reverses it.
