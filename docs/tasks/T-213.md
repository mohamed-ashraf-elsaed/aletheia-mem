## Goal

Transitions and Web Animations with tokens, and a reduce path.

## Files to touch

## What changed

- `public/ui-motion.js` (added with the component system) is now covered by tests: reduced motion turns every movement into an 80 ms fade, a move-only animation (shake) does nothing, enter and leave keep to opacity and transform, leave holds its end state, expand and collapse animate height (the one layout property, as the task asks), count-up always ends on the final value, durations are read from the CSS tokens, and a hidden page marks the root so loops pause.
- `public/ui-components.js` and `public/ui-components.css`: the tab indicator is now a 1 px bar moved and stretched with `transform` only (it animated `width` before). Memory, Review and other `.ui-item` cards lift 1 px on hover.
- `test/ui-motion.test.mjs` reads the stylesheets: tokens are 120, 200 and 320 ms; the reduced-motion block sets animation and transition durations to 0.01 ms and iteration count to 1; no transition uses `all`; every transition names its property and uses a duration token; no keyframe touches a layout property; looping animations exist only for skeletons, spinners, status dots, the brain loader and progress bars, and pause under `:root[data-hidden]`.
- Chromium check (Playwright, `prefers-reduced-motion` emulated both ways, seeded server): an idle page has no infinite animation; opening a dialog runs 160 to 320 ms transform and opacity animations; with `reduce` it runs 80 ms opacity fades only and the CSS tokens read 0.01 ms.
- Known and by design: loading marks (skeleton shimmer, spinner, indeterminate bars, the brain loader) and the pulse of a working status loop while the thing they show is happening, and pause when the tab is hidden.

## Acceptance criteria

- [x] prefers-reduced-motion removes movement.
