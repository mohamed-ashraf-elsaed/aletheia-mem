## Goal

`GET /v1/context/economics` (and `aletheia context economics`) reports per-observation read tokens counted from
stored text with one documented counter, and work tokens only where a real usage record exists. Where no record
exists, the value is `null` and labelled — never guessed.

## Files to touch

- `src/hub/economics.mjs` (new)
- `src/hub/routes.mjs`
- `bin/aletheia.mjs`
- `test/economics.test.mjs` (new)

## What changed

- `economics(store, {project, limit})` lists context observations (memories of kind observation, summary or note)
  with `readTokens` from `estimateTokens` (four characters per token, the one documented counter) and per-observation
  `workTokens: null` labelled "usage is recorded per extraction call, not per observation".
- Totals sum read tokens, take work tokens as `fact_usage` input + output (or `null` with "no usage record"), and
  compute a savings percent only when work tokens exist and exceed zero.
- `GET /v1/context/economics` wires the module; `aletheia context economics` prints the same JSON.

## Acceptance criteria

- [x] Read tokens are counted from text; work tokens come from the usage ledger.
- [x] No usage record means work tokens are null and labelled.
- [x] The route and the CLI answer with the same shape.
