## Goal

Detect duplicate, conflicting, too-long and oversized rule sets before sync.

## Why

D1 F-L08. See [20-claude-mem-feature-matrix.md](../20-claude-mem-feature-matrix.md) and, where relevant,
[22-improve-the-numbers.md](../22-improve-the-numbers.md) or [23-memory-building.md](../23-memory-building.md).

## Files to touch

- `src/hub/rule-lint.mjs` (new): duplicate, contradiction, size, safety, secret and drift checks.
- `bin/aletheia.mjs`: `aletheia rules lint [--dir] [--tools] [--json]`.
- `test/rule-lint.test.mjs` (new): the validation test.
- `docs/25-installers.md`: the command and the finding codes.

## Steps

1. Normalise text and compare duplicates.
2. Detect direct contradictions (always/never pairs).
3. Warn above a size budget.
4. Return warnings; do not block sync.

Deviation, 2026-10-26: a contradiction is a direct same-scope, same-condition, opposite-polarity pair with the
same core words. The lint does not try to infer semantic conflicts between differently worded rules. Drift is
checked only in files that contain the managed-block markers; a user-authored file without them is skipped.

## Acceptance criteria

- [x] Duplicate rules are reported once.
- [x] A direct contradiction is reported.
- [x] A clean set has zero warnings.
- [x] Every finding has a rule id and a fix hint.
- [x] Safety instructions, secrets, long rules, oversized sets and managed-block drift are reported.
