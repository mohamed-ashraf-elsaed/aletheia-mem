# T-152: Group sessions into requests with status, stage and detail

## Goal

Group recent sessions into one card per human request: sessions of one goal (the owner's own imperative prompt) in one
project, close in time, form one request. Every number and status comes from a stored row. No model is needed.

## Why

claude-mem's My Work shows one card per request with a status, stage, started time and "Where this came from".
Aletheia had sessions, goals and summaries but nothing tying sessions into one request. Seen by the owner on
2026-10-27; the full gap list is in `aletheia-private/claude-mem-gap-report.md`. The build-story half of the original
T-152 moved to T-169.

## What changed

- `proposeRequests(store, {project, now, maxGapHours, activeMinutes, limit})` merges the memory and episode views of
  each session, derives a goal key from the first imperative prompt (`goals.mjs`), groups by (project, goal key), and
  splits a group into separate requests when the gap between consecutive sessions is more than `maxGapHours` (24 h).
  Sessions with no imperative prompt share a "no-goal" key. It returns `requests`, `dismissedRequests`, `counts`
  (working, idle, shipped, waitingOnYou, total) and `empty`.
- Each request carries status (Working / Idle / Shipped / Waiting on you), stage (the goal object), started time,
  running time, session/prompt/tool counts and evidence ids (session, prompt and tool ids).
- `requestDetail(store, {requestId, project})` returns the request plus `whereThisCameFrom`: sessions, the owner's
  prompts and source facts, each with ids and timestamps.
- `requestAction` dismisses or restores a request id in a settings list (reversible, never a delete).
- Routes: `GET /v1/work/requests`, `GET /v1/work/requests/:id`, `POST /api/hub/requests/:id` (dismiss/restore).

## Acceptance criteria

- [x] Sessions of one goal in one project form one request, with evidence ids.
- [x] Each request shows Working, Shipped, Waiting on you or Idle from stored rows.
- [x] The detail shows where this came from: sessions, prompts and facts.
- [x] Dismiss and restore are reversible; an empty store says `empty: true` with no placeholder numbers.
