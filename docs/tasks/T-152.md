## Goal

Group recent sessions into overall requests, show each request's progress from stored facts, and write a build story
in the Work tab. Every number comes from the database. No model is needed for the first version.

## Why

claude-mem's My Work shows a "Build story" (requests shipped, requests waiting on the owner), progress meters and
shipping velocity. Aletheia has sessions, goals and summaries, but nothing that ties sessions into one request.
Seen by the owner on 2026-10-27. The full gap list comes from `aletheia-private/claude-mem-gap-report.md`.

## Files to touch

- `src/hub/requests.mjs`
- `src/hub/routes.mjs`
- `public/tabs/work.js`
- `test/requests.test.mjs`

## Steps

1. Group sessions into requests (same goal, same project, close in time). Rule-based first, with the evidence ids.
2. Give each request a status from stored facts and session ends: in progress, shipped, waiting on the owner.
3. Add `GET /v1/work/requests` and a Build story panel with counts and a velocity line, empty state included.
4. Tests on a seeded database. Reversible dismiss, as for goals.

## Acceptance criteria

- [ ] Sessions of one goal in one project form one request, with evidence ids.
- [ ] Each request shows in progress, shipped or waiting on the owner, from stored rows.
- [ ] The empty state says what to do and shows no placeholder numbers.
