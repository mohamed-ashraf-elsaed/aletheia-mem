## What changed

- `public/ui-status-model.js`: nine indicators (server, database, search index, vectors, embedding model, queue, extractor, last capture per tool, sync) plus Live or Polling, built only from API answers; a source that has not answered is "unknown". Includes the overall state for the favicon, new-error and recovery detection, retry delays (2, 4, 8, 16, 30 s) and frame parsing.
- `public/ui-status.js`: controller with injectable timers, network and socket. Polls `/v1/health`, `/v1/work` and `/api/hub/sync/status` (and `/api/hub/overview` every sixth pull) with backoff; pauses while the page is hidden and pulls at once when shown; opens `/v1/live` (the WebSocket merged from the hardening branch) and falls back to polling when it closes, reconnecting after 5, 10, 20, 60 s; a change frame triggers one light refresh. Draws the strip: dot and label per indicator, hover or focus opens a popover with details and the exact command to fix it (click pins it), new errors shake once and are announced, "updated 3 s ago", a refresh button that spins. A connection-lost banner slides in with a countdown and Retry now, and slides out on recovery with a toast. The favicon shows idle, working or error.
- `public/one-ui.css`: status strip styles; other indicators dim while offline.
- Checked in Chromium against the seeded server: all ten items render with live data, the popover shows per-tool capture times, killing the server shows the banner with a counting-down retry and a red favicon, restarting it clears the banner and reconnects the socket.

## Acceptance criteria

- [x] Each indicator maps a real API field to a state.
- [x] Polling backs off, pauses when hidden and falls back from the WebSocket if one exists.
