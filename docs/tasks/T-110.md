# T-110: Add remote login for the Hub

Status: validated
Phase: P6
Depends on: T-104
Validated on: 2026-10-26
Evidence: see the Validation section below.

## Goal

Password plus optional TOTP session login so the Hub can be used remotely; safe defaults stay loopback-only.

## Why

The owner decided on 2026-10-26 that every paid feature of claude-mem and its rivals is built here for free and self-hosted. D7 `docs/27-free-paid-parity.md` feature F10; research in [27-free-paid-parity.md](../27-free-paid-parity.md).

## Files to touch

- `src/hub/login.mjs` (new): the login guard. Admin token → HttpOnly SameSite=Strict Secure-when-HTTPS session
  cookie + readable CSRF cookie; expiry; lock-out with back-off; the inline login page.
- `src/server.mjs`: wires the guard; remote mode (non-loopback bind) requires a session for `/` and `/api/*`
  and a CSRF header on state-changing requests; `guarded()` steps aside in remote mode; new options
  `requireLogin`, `behindTls`, `sessionTtlMs`, `loginLockMs`, `loginMaxFailures`.
- `src/config.mjs`, `bin/aletheia-server.mjs`: `ALETHEIA_HOST`/`--host` and `ALETHEIA_BEHIND_TLS`/`--behind-tls`;
  a non-loopback bind without the TLS flag prints a warning.
- `public/ui-dom.js`: `api()` echoes the CSRF cookie in `X-CSRF-Token` for non-GET calls.
- `docs/27-free-paid-parity.md`, `docs/29-sync.md` (§29.5), `docs/manual-test.md` (§10, NOT RUN BY AUTHOR).
- `test/hub-login.test.mjs` (new): the validation test.

## Steps

1. Read the feature section and the shared design in docs/27 and `docs/research/`.
2. Write the failing test named below first.
3. Implement the smallest version that passes; record any deviation from the design here with a date.
4. Run the validation command and paste the real output.

Deviation, 2026-10-26 (from A1 F10): the design said a scrypt password plus optional TOTP. The owner's work
order for this task says login exchanges a device-level admin token for the cookie, so the sync account's admin
token (T-104/T-108) is the credential and there is no separate password hash. TOTP is not built; nothing claims
it. Sessions live in memory (a restart ends them); that is stated in docs/manual-test.md §10.

## Acceptance criteria

- [x] The behaviour in Goal is observable in the test (401 without a session, 403 without CSRF, cookie flags,
  expiry, logout, lock-out with back-off).
- [x] Nothing leaves the machine unless the user configured a remote (loopback-only keeps today's behaviour;
  login turns on only for a non-loopback bind or an explicit `requireLogin`).
- [x] Failure modes listed in docs/27 for this feature are each tested or marked not built (lost password → the
  admin token is minted on the hub machine, docs/manual-test §10; cookie theft → short-lived sessions and
  HttpOnly+SameSite=Strict, expiry tested; TOTP → not built, recorded above).
