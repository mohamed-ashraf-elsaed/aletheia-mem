Status: validated

## Goal

Advisory WebSocket frames tell other devices to pull; polling remains the source of truth.

## Why

The owner decided on 2026-10-26 that every paid feature of claude-mem and its rivals is built here for free and self-hosted. D7 `docs/27-free-paid-parity.md` feature F5; research in [27-free-paid-parity.md](../27-free-paid-parity.md).

## Files to touch

- `src/hub/live.mjs` (new): the socket set, project scope and dismissed filtering.
- `src/server.mjs`: `/v1/live` upgrade (local-only guard, optional bearer key, Origin check) and the
  `websocket` handler; fact frames from the extraction worker.
- `src/hub/routes.mjs`: `session` frames after `/v1/memories`, `/v1/events`, `/api/hub/memories`;
  `review` frames after `/api/hub/review/:id`.
- `src/hub/queue.mjs`: `executeJob` returns `factIds` and `project`.
- `public/tabs/work.js`: connect to `/v1/live` and refresh on a frame; keep the 10 s poll as the fallback.
- `test/sync-live.test.mjs` (new): the validation test.

## Steps

1. Read the feature section and the shared design in docs/27 and `docs/research/`.
2. Write the failing test named below first.
3. Implement the smallest version that passes; record any deviation from the design here with a date.
4. Run the validation command and paste the real output.

Deviation, 2026-10-26: frames are advisory and carry `{kind, id, project}` only (no payload text). The
client refreshes the overview on any frame and keeps the existing 10-second poll as the source of truth.

## Acceptance criteria

- [x] The behaviour in Goal is observable in the test (frames after a write, unauthenticated and bad
  Origin refused, reconnect, no frames for dismissed or out-of-scope projects).
- [x] Nothing leaves the machine unless the user configured a remote (the socket is loopback only).
- [x] Failure modes listed in docs/27 for this feature are each tested or marked not built (bad Origin and
  unauthenticated are refused; the client falls back to polling).
