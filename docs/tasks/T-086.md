# T-086: Build the docs site with one page per document

Status: validated
Phase: P4
Depends on: T-013
Validated on: 2026-10-26
Evidence:

## Goal

Generate a static page per numbered doc, a full sitemap and structured data, from the Markdown source.

## Why

D1 F-P05 to F-P07; D5 section 24.4. See [20-claude-mem-feature-matrix.md](../20-claude-mem-feature-matrix.md) and, where relevant,
[22-improve-the-numbers.md](../22-improve-the-numbers.md) or [23-memory-building.md](../23-memory-building.md).

## Files to touch

- `scripts/build-site.mjs`
- `scripts/check-sitemap.mjs`
- `site/index.html`
- `site/style.css`
- `site/robots.txt`
- `site/sitemap.xml`
- `site/docs/*.html` (generated)
- `test/site.test.mjs`

## Steps

1. Render Markdown with a small dependency-free renderer.
2. Generate a docs index and per-doc pages.
3. Add `TechArticle` and `FAQPage` JSON-LD.
4. Generate the sitemap from the file list with git dates.

Deviation, 2026-10-26: the site covers the top-level documents in `docs/` (30 pages), not `docs/tasks/`,
`docs/research/`, `docs/verification/` or `docs/i18n/`. Those are a task log, raw research, fixtures and
translations; docs/24 specifies "one page per numbered doc". Links from a page to those directories go to GitHub.

## Acceptance criteria

- [x] Every top-level doc has a page.
- [x] The sitemap URL count equals the page count.
- [x] JSON-LD validates.

## Validation command

```bash
bun scripts/build-site.mjs && bun scripts/check-sitemap.mjs
```

Expected: site built; sitemap matches pages
