## Goal

`#/work/session/<id>` shows one session: prompts, tool events, the summary and the extracted facts with sources.
It is read-only; there is no accept, dismiss or delete action on this page.

## Files to touch

- `src/hub/work.mjs`
- `src/hub/routes.mjs`
- `public/work-view.js`
- `public/tabs/work.js`
- `test/work-views.test.mjs`
- `test/work.test.mjs`

## What changed

- `sessionDetail(store, {sessionId, project})` returns the ordered timeline (prompt, tool event, other episode
  kinds, then the summary), the facts with their source episode id/ref/text, and the session counts.
- `GET /v1/work/session/:id?project=` returns `{session}` or 404; `work.test.mjs` covers the success and missing id.
- `public/work-view.js` shapes the session for the DOM: title, meta, summary, timeline labels and fact source
  labels. `public/tabs/work.js` renders it with a back link to the overview and no action buttons.
- A session with no timeline or facts renders empty text, not a fabricated row.

## Acceptance criteria

- [x] The timeline has prompts, tool events and the summary in time order.
- [x] Extracted facts show their source episode and status.
- [x] The page is read-only, with no actions in the view model.
- [x] An unknown session is 404 on the API and a clear message in the UI.
