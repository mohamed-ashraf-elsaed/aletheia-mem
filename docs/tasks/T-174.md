# T-174: Stop the test fixture leaking temp directories

Status: validated
Phase: P0
Depends on: none
Validated on: 2026-10-27
Evidence:

## Goal

Every test run left one `/tmp/work-view-fixture-*` directory behind, because `test/fixture.mjs` created it with
`mkdtempSync` and nothing removed it. Register fixture directories with the T-165 registry and clean them once, after
the whole run, from a `bunfig.toml` test preload.

## Why

A single `bun test` run left dozens of fixture directories (each with a SQLite file). Repeated runs fill `/tmp` and
make the "leftover temp dirs" check useless.

## Files to touch

- `bunfig.toml` (new): `[test] preload = ["./test/preload-cleanup.mjs"]`.
- `test/preload-cleanup.mjs` (new): registers one `afterAll(cleanupTempDirs)` for the whole run.
- `test/fixture.mjs`: create the fixture directory through `tempDir("work-view-fixture-")`.
- `test/temp-dirs.test.mjs`: a test that makes a fixture and fails if its directory survives cleanup.

## What changed

- A probe proved that Bun 1.3.10 does fire an `afterAll` registered from a file named in `bunfig.toml` `[test] preload`,
  so the single global cleanup is used rather than an `afterAll` in every fixture-using file. The probe was run in a
  scratch directory on 2026-10-27: the preload's `afterAll` wrote `after.txt` after the one test passed.
- `test/fixture.mjs` now calls `tempDir("work-view-fixture-")` from `test/temp-dirs.mjs`, so every fixture is
  registered when it is created.
- `test/preload-cleanup.mjs` runs `cleanupTempDirs()` once after the suite.
- `test/temp-dirs.test.mjs` gains a test that creates a fixture, runs the cleanup, and asserts the fixture directory
  is gone. It fails if a fixture directory survives.
- The validation's directory prefix is `work-view-fixture-` (the fixture's real prefix); the earlier prompt text
  showed a mangled path, so the real prefix is used here.

## Acceptance criteria

- [ ] `bun test` passes.
- [ ] After `bun test`, `ls -d /tmp/work-view-fixture-*` finds no directories.
- [ ] A test fails if a fixture directory survives cleanup.

## Validation command

```bash
nice -n 10 bun test
ls -d /tmp/work-view-fixture-* 2>/dev/null | wc -l
```

Expected: all tests pass, and the count printed is `0`.
