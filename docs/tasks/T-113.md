## Goal

Delete a user's data everywhere, export everything first, and return a receipt; optional crypto-erase.

## Why

The owner decided on 2026-10-26 that every paid feature of claude-mem and its rivals is built here for free and self-hosted. D7 `docs/27-free-paid-parity.md` feature F14; research in [27-free-paid-parity.md](../27-free-paid-parity.md).

## Files to touch

- `src/hub/erasure.mjs` (new): plan, apply, pre-erase export, HMAC key/receipt.
- `src/hub/sync/client.mjs`: `erase()` for the local replica and outbox.
- `src/hub/sync/store.mjs`: `findEntities()` and a unique, content-free server tombstone per purged entity.
- `src/hub/routes.mjs`, `src/config.mjs`: the guarded erasure routes and key/export/receipt paths.
- `bin/aletheia.mjs`: `aletheia erase` and `aletheia erase verify`.
- `test/erasure.test.mjs` (new): the validation test.
- `docs/03-http-api.md`, `docs/27-free-paid-parity.md`.

## Steps

1. Read the feature section and the shared design in docs/27 and `docs/research/`.
2. Write the failing test named below first.
3. Implement the smallest version that passes; record any deviation from the design here with a date.
4. Run the validation command and paste the real output.

Deviation, 2026-10-26: `--apply` always writes a pre-erase bundle (default under the data dir) because the task
requires export first; that file is the one copy expected to hold the content. `SyncStore.purgeEntity` needed two
fixes to make a multi-row erase correct: the server tombstone now gets a unique device sequence (the old fixed `0`
collided on the second entity) and clears `sync_head.payload` (the old head kept the content). Crypto-erase of an
E2EE account is not added: deleting wrapped keys would make the local plaintext copy unreadable too, and the task
does not require it.
