## Goal

Rules on audit events (new device, bulk export, failed logins) that call a webhook or write a feed.

## Why

The owner decided on 2026-10-26 that every paid feature of claude-mem and its rivals is built here for free and self-hosted. D7 `docs/27-free-paid-parity.md` feature F15; research in [27-free-paid-parity.md](../27-free-paid-parity.md).

## Files to touch

- `src/hub/alerts.mjs` (new): rules, event log, delivery queue, SSRF guard, HMAC signing, retries, file target.
- `src/hub/sync/server.mjs`, `src/hub/queue.mjs`, `src/server.mjs`: event emission and the delivery loop.
- `src/hub/routes.mjs`, `src/config.mjs`: the guarded alert routes and `alertsDb`.
- `bin/aletheia.mjs`, `bin/aletheia-sync.mjs`: `aletheia alerts ...`, delivery enabled on the sync hub.
- `public/tabs/alerts.js` (new only; the UI shell is wired by the UI agent later).
- `test/alerts.test.mjs` (new): the validation test.
- `docs/03-http-api.md`, `docs/27-free-paid-parity.md`.

## Steps

1. Read the feature section and the shared design in docs/27 and `docs/research/`.
2. Write the failing test named below first.
3. Implement the smallest version that passes; record any deviation from the design here with a date.
4. Run the validation command and paste the real output.

Deviation, 2026-10-26: the built event set is the one named in the request: `extraction.failed`, `queue.depth`,
`sync.error`, `device.paired`, `token.revoked`, `quota.hit`. The task file's illustrative "bulk export" and
"failed login" rules are not built; adding an event is a one-line entry in `ALERT_EVENTS` plus an `emit` at the
call site. The "security alerts" product described on the vendor page stays UNVERIFIED; this is our own rule
engine. A webhook target that does not resolve is refused (fail closed) rather than attempted.
