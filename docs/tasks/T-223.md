# T-223: Generate a one-file project status page from the repository

Status: validated
Phase: P4
Depends on: none
Validated on: 2026-10-27
Evidence:

## Goal

One self-contained HTML file the owner opens in Visual Studio Code or any browser that shows the whole project state,
rebuilt from the repository's real files with one command.

## Files to touch

- `scripts/gen-status.mjs`
- `scripts/status-page.css`
- `scripts/status-page.js`
- `test/gen-status.test.mjs`
- `docs/status/README.md`
- `docs/status/index.html`
- `docs/status/status.json`
- `docs/screenshots/status-light-1280.webp`
- `docs/screenshots/status-dark-375.webp`
- `package.json`
- `.github/workflows/ci.yml`

## Steps

1. Parse TASKS.md, every `T-*.md`, the feature tables in documents 20 and 27, the UNVERIFIED lists, the docs folder, git, the workflow files, routes and CLI commands.
2. Derive eligible, blocked, stale and inconsistent tasks, and a ranked next list.
3. Write one HTML file (inline CSS and JS, data as a JSON script block) and `status.json`.
4. `--check` compares the parts that depend only on the files, not the time, sha or git history.
5. Add the `--check` step to the existing CI workflow.

## Acceptance criteria

- [x] `bun scripts/gen-status.mjs` writes `docs/status/index.html` and `docs/status/status.json` from the real files; every number is computed.
- [x] The page has no external URL, no `innerHTML` and no inline event handler attribute.
- [x] `--check` exits 1 on a stale file and 0 after regeneration.
- [x] The test suite does not run inside the generator; test results are shown as the last recorded run.
- [x] The page was opened over `file://` at 1280 and 375 px, light and dark, with zero console errors.

## Validation command

```bash
bun test test/gen-status.test.mjs && bun scripts/gen-status.mjs --check
```

Expected: 0 fail, then `gen-status: ok`.
