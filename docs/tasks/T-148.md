# T-148: Fix the transcript back-fill CI flake

Status: validated
Phase: P6
Depends on: T-121
Validated on: 2026-10-26
Evidence: see the Validation section below.

## Goal

Make `aletheia import transcripts` deterministic so the CI suite does not fail depending on the order
the filesystem returns session files.

## Why

GitHub Actions run 40369395249 (commit "bring in Aletheia's own Work tab", 2026-10-26 17:31 UTC)
failed two T-121 tests: `queued` was 2 where the test expected 3. The importer only queued a session
when it wrote at least one new episode in that run. When two sessions share the same redacted turn, one
session's only turn dedupes against the other and that session is silently never queued. Which session
dedupes depends on `findTranscripts`, which sorts only by file mtime and leaves equal mtimes in the
filesystem's directory order — different on the CI runner than on this machine.

## Files to touch

- `src/hub/transcripts.mjs`: queue one job per session that has an in-scope episode, independent of
  whether the run inserted a new row; add a path tie-break to the mtime sort.
- `test/transcript-backfill.test.mjs`: a regression test that forces the CI order and asserts both
  sessions are queued.

## Steps

1. Read the failed CI log and find the failing assertions.
2. Reproduce the order dependence locally with a controlled mtime pair.
3. Fix the root cause in `importTranscripts` and add the deterministic sort tie-break.
4. Run the validation command and paste the real output.
