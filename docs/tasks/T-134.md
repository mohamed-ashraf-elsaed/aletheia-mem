# T-134: Build one app shell with Work, Memory, Rules and Tools tabs

Status: validated
Phase: P6
Depends on: none
Validated on: 2026-10-26
Evidence: see below.

## Goal

One HTML page at `/` with a tab bar for Work, Memory, Rules and Tools, hash routes `#/work`, `#/memory`,
`#/rules`, `#/tools`, and a shared header: project selector, a memory search box that works from any tab, and a
health dot from `/v1/health`. The existing Work page keeps working inside the Work tab, unchanged.

## Why

Today "My Work" (`/`) and "Memory Hub" (`/hub`) are two pages. One app removes the split and gives every feature a
single address. Part A of the `feat/one-ui` work order.

## Files to touch

- `public/index.html`: the shell. Still contains `<div id="root">` and the existing Work bundle, plus the tab
  containers, header and the two new scripts.
- `public/one-ui.css`: shell styles; dark and light through the existing `prefers-color-scheme` variables.
- `public/ui-core.js`: DOM-free router, tab list and view helpers (T-139 imports these).
- `public/ui-dom.js`: shared text-node DOM builder, API helper, toast and the audit panel.
- `public/one-ui.js`: tab bar, hash routing, project selector, search box and health dot. Tab modules are loaded
  on first visit from `public/tabs/`.
- `src/hub/routes.mjs`: `/hub` is now a 200 HTML redirect to `/#/memory`; `/v1/health`; and the additive JSON
  routes the tabs read (`/api/hub/facts`, `/review`, `/rule-suggestions`, `/doctor`). The routes landed with the
  shell so each later tab commit only adds its own module.

## Acceptance criteria

- [x] One page, four tab containers, four hash routes; unknown hashes fall back to Work.
- [x] The Work tab is the existing Work bundle mounted at `#root`, unchanged.
- [x] The header has a labelled project selector, a search box and a health dot.
- [x] `/hub` redirects to `#/memory` and `/hub/app.js` still answers (the old test stays green).
