# T-149: Raise the sync E2EE scrypt cost to the OWASP minimum

Status: validated
Phase: P6
Depends on: T-117
Validated on: 2026-10-26
Evidence: see the Validation section below.

## Goal

Raise the scrypt KDF for NEW sync E2EE accounts to the current OWASP minimum and store the KDF
parameters per wrapped key, so old accounts still unlock and can be upgraded in place.

## Why

`src/hub/sync/e2ee.mjs` derived the KEK with N=16384, r=8, p=1. The OWASP Password Storage Cheat
Sheet now lists scrypt N=2^17 (131072), r=8, p=1 as the minimum (source fetched 2026-10-26, URL in the
research log). Unlock used a compile-time constant, so raising it would have locked out existing
accounts. Parameters must be read from the record.

## Files to touch

- `src/hub/sync/e2ee.mjs`: `DEFAULT_KDF` N=2^17, `deriveKek(passphrase, salt, params)`.
- `src/hub/sync/store.mjs`: `enableE2ee`/`rotateE2eeKey`/`changePassphrase`/`purgePlaintext` read the
  per-key `params`; new `upgradeE2eeKdf` re-wraps every data key without touching op ciphertext.
- `src/hub/sync/client.mjs`: `unlockE2ee` passes the record's params to `deriveKek`.
- `src/hub/sync/cli.mjs`, `bin/aletheia.mjs`: `aletheia sync upgrade-kdf --passphrase <p>`.
- `docs/29-sync.md`: dated correction to §29.6.
- `test/sync-e2ee.test.mjs`: old-params unlock, upgrade, wrong-passphrase, params-from-record tests.
- `docs/tasks/research-log.md`: the OWASP fetch.

## Steps

1. Fetch the OWASP Password Storage Cheat Sheet and take its lowest scrypt setting.
2. Store per-key params, read them at unlock, and add `upgrade-kdf`.
3. Add the tests and run the validation command.
4. Measure one derivation and record the machine.

## Acceptance criteria

- [x] Old-parameter account still unlocks (params read from the record, not a constant).
- [x] `upgrade-kdf` re-wraps the data key under the new default and leaves op ciphertext byte-identical.
- [x] A wrong passphrase is refused.
- [x] One derivation time is measured with a real command and the machine is stated.
