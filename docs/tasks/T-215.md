## What changed

- The hardening branch had been merged into main before this task, so the Work tab was restyled on top of its changes (its Work polish, sessions and goals logic, and the WebSocket frames), and its JavaScript was changed.
- `public/tabs/work.js`: rebuilt on the shared components. A small overview request (`/v1/work?sessions=1&facts=8&review=6`) feeds the six tiles (counts animate), at most six "needs you" items (with the total and links to the full paged pages) and eight recent facts. Sessions and goals are server-paged lists (`/v1/work/sessions`, `/v1/work/goals`) with the page in the URL hash, a state filter, an id filter, and cards with prompt, summary and fact count. Accept, Reject, Dismiss, Restore, Pin and Unpin are optimistic with an 8 s Undo and roll back on failure; accepting a rule suggestion can be undone, which also turns the new rule off. An empty hub shows the first-run guide instead of the old instruction card. The session page uses a Region (skeleton, error with Retry), the safe Markdown view for the summary, the shared timeline and fact cards.
- The tab no longer opens its own WebSocket: the status bar owns the one socket and announces each change frame as an `aletheia:frame` event, which refreshes Work after a 500 ms pause. The 10 s timer stays as the fallback and pauses while the page is hidden.
- `src/hub/lists.mjs`: each session row also carries its latest summary and fact count.
- `test/ui-work.test.mjs`: 13 tests. Existing Work tests (`work`, `work-views`, `work-ui-contract`, `work-goals`, `sync-live`) pass unchanged.
- Checked in Chromium on the seeded server: tiles, 10 sessions per page of 42, page 2 in the URL, opening a session and Back returning to page 2, no console errors, no stray "null" text.
- Task order: T-214 (accessibility pass) now depends on this task, so its row says so.
