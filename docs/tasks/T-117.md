# T-117: Add optional end-to-end encryption for sync

Status: validated
Phase: P6
Depends on: T-102
Validated on: 2026-10-26

## Goal

Encrypt payloads on the device so the hub stores ciphertext only; document key handling and recovery.

## Why

The owner decided on 2026-10-26 that every paid feature of claude-mem and its rivals is built here for free and self-hosted. D7 `docs/27-free-paid-parity.md` feature F4; research in [27-free-paid-parity.md](../27-free-paid-parity.md).

## Files to touch

- `src/hub/sync/e2ee.mjs` (new): AES-256-GCM payload/wrap/decrypt, scrypt KEK derivation (N=16384, r=8, p=1),
  random 256-bit data keys, the `@e2ee` envelope, nonce/AAD handling.
- `src/hub/sync/store.mjs`: `sync_e2ee_key` table, `e2ee`/`current_kid` account columns (additive, with a
  backup copy before any ALTER), `e2eeStatus`, `enableE2ee`, `rotateE2eeKey`, `changePassphrase`,
  `plaintextStats`, `purgePlaintext`; `pull`/`status` now carry the `e2ee` flag.
- `src/hub/sync/server.mjs`: `GET /v1/sync/e2ee` returns the wrapped keys to a joined device.
- `src/hub/sync/client.mjs`: sealing in `writeLocal` before the outbox, decryption at read time, `unlockE2ee`,
  `importRecoveryKey`, `exportRecoveryKey`, re-sealing of queued plaintext ops at push, the
  account-is-E2EE-without-a-key refusal.
- `src/hub/sync/cli.mjs`, `bin/aletheia.mjs`: `enable-e2ee`, `unlock-e2ee`, `rotate-key`,
  `change-passphrase`, `export-recovery-key --out <file>` (0600), `purge-plaintext [--apply]`.
- `src/hub/routes.mjs`, `public/tabs/tools.js`: the E2EE status line in the Sync section.
- `docs/29-sync.md` (§29.6, written before the code), `docs/27-free-paid-parity.md`, `docs/manual-test.md`
  (§8 E2EE, NOT RUN BY AUTHOR), `docs/tasks/unverified.md` (row 45).
- `test/sync-e2ee.test.mjs` (new): the validation test.

## Steps

2. Write the failing test named below first.
3. Implement the smallest version that passes; record any deviation from the design here with a date.
4. Run the validation command and paste the real output.

Deviations, 2026-10-26 (from A1 A-SYNC and F4):
- A1 suggested a one-time enrollment code that carries the wrapped DK. A device joins with the ordinary
  pairing code and then fetches the wrapped keys over `/v1/sync/e2ee`; the passphrase unwraps them. The
  recovery file (the printed recovery key of A1) is the data keyring itself, exported by the device with
  mode 0600.
- A1's "unlock mode" for server-side recall is not built: with E2EE on, server-side search/remote MCP
  return ciphertext, and local device search is the way to read. Stated in docs/29 §29.6.
- `purge-plaintext` re-encrypts old bodies in place (the server has no plaintext-drop alternative that keeps
  replicas convergent); it prints what it will do and only acts with `--apply` plus the passphrase.

## Acceptance criteria

- [x] The behaviour in Goal is observable in the test (ciphertext on the wire and in the server DB, tamper
  rejection, nonce uniqueness over 10,000 ops, wrong-passphrase failure, two-device convergence, server
  compromise simulation, no plaintext in audit, rotation, passphrase change, recovery file 0600,
  purge-plaintext, unencrypted accounts unchanged).
- [x] Nothing leaves the machine unless the user configured a remote (E2EE only changes what a configured
  sync pushes; nothing new is sent anywhere by itself).
- [x] Failure modes listed in docs/27 for this feature are each tested or marked not built (lost passphrase
  and recovery key = data loss, documented in docs/29 §29.6; changing the DK = rotate-key, tested; wrong key
  or tampered ciphertext, tested; unlock mode, not built, recorded above).
