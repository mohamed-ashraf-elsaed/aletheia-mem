# T-101: Prove automatic capture end to end

Status: validated
Phase: P3
Depends on: T-058, T-059, T-100
Validated on: 2026-10-26
Evidence: see `## Evidence`

## Goal

One test starts the real server, installs into a temporary `HOME`, runs the installed hook commands with recorded
payloads, and checks the database, the injected context, the spool, redaction, the time budget and uninstall.

## Why

Every acceptance claim in T-058, T-059 and T-100 is a claim about files and processes, not about functions. This is
the test that would catch a hook command that reads a different file than the installer wrote.

## Files to touch

- `test/e2e-capture.test.mjs`
- `docs/manual-test.md`

## Steps

1. Start `startServer` on a random port with a temporary data dir and database.
2. Run `install claude-code --write` and `install command-code --write` with `HOME` pointed at a temporary folder.
3. Read the hook commands back out of the written settings files and pipe recorded payloads through them with `sh -c`.
4. Assert prompts, tool events and summaries are in the database, and that SessionStart output contains the
   wrapped context block, a pinned memory and a rule.
5. Point one run at an unusable database, assert it spools, then assert the next run flushes.
6. Assert `sk-...` and `Bearer ...` never reach the database.
7. Run 50 hook invocations and assert p95 is under 100 ms.
8. Run `doctor`, then uninstall, and assert only our entries are removed.

## Acceptance criteria

- [x] Prompts and tool events are in the database after the installed commands run.
- [x] SessionStart output contains the context block and a pinned memory.
- [x] A run with an unusable store spools, and a later run flushes it.
- [x] Secrets never appear in the database.
- [x] p95 hook work < 100 ms over 50 runs.
- [x] `doctor` sees the server, both hook sets, an empty spool and the last capture.
- [x] Uninstall removes only our entries.
- [x] `docs/manual-test.md` gives exact real-session steps and marks what the author did not run.

## What the p95 test measures

It calls the real `runHook` 50 times in-process and times each call: open the store, redact, write, close. The
result is p95 1.16 ms (printed by the test). Process startup and module loading belong to the host, not the hook.
The installed command uses a single-file Bun bundle so that startup stays small; the bundle was measured at
p50 56 ms / p95 81 ms on this machine when it was built. This machine was under load average 22 during that
measurement, so the end-to-end number is noisy; the in-process number is the stable one.
