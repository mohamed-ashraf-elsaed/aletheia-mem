## Goal

A written, testable way to cut the next npm release and GitHub tag. Agents prepare files and check them. The owner
runs publish, tag and push.

## Files to touch

- `docs/releasing.md`
- `scripts/release.mjs`
- `.github/workflows/release.yml`
- `test/release.test.mjs`, `test/release-files.test.mjs` (the old "no release workflow" assertion)
- `CHANGELOG.md`, `docs/tasks/TASKS.md`, `docs/tasks/T-225.md`, `docs/tasks/unverified.md`, `docs/status/`

Not touched: `src/`, `bin/`, `public/`. Nothing is published, tagged or pushed.

## Steps

1. Write `docs/releasing.md` (policy, sequence, owner steps, rollback).
2. Add `--prepare <version>` and `--verify [--tag vX.Y.Z]` to `scripts/release.mjs`; keep the pack check.
3. Add the tag workflow, gated on trusted publishing or `NPM_TOKEN`.
4. Test all of it on a temp git repository.

## Acceptance criteria

- [x] `--prepare` refuses a dirty tree, a branch other than main, a version not greater than package.json or the CHANGELOG, and empty notes.
- [x] `--prepare` bumps package.json and moves Unreleased into a dated section without committing or tagging.
- [x] `--verify` checks version equality, the tag, required pack files, unpacked size (12 MB), absolute README image URLs and no relative link in the first 60 README lines.
- [x] The workflow runs on `v*` tags, publishes only when configured, and the setup is documented in comments.
- [x] No npm publish, tag, push or release was made.
