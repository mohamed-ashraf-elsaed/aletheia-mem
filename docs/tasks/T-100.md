# T-100: Add the Command Code installer and hooks

Status: validated
Phase: P3
Depends on: T-058
Validated on: 2026-10-26
Evidence: see `## Evidence`

## Goal

`aletheia install command-code --write` registers the MCP server, merges hooks into the user settings and writes
the rules block, with the same backup, manifest, idempotence and uninstall rules as Claude Code.

## Why

Command Code is the other host this project is used from. It has a documented user settings file and four hook
events, so it can capture tool events and inject context without a plugin. It cannot capture prompts or session
ends, and the installer and docs must say so rather than pretend.

## Files to touch

- `src/hub/install.mjs`
- `src/hub/hooks/command-code.mjs`
- `src/hub/tools.mjs`
- `test/install-claude.test.mjs`
- `docs/25-installers.md`

## Steps

1. Read the real format from the Command Code bundled reference and the real files on this machine.
2. Add `command-code` to the tool registry with its `{transport: "stdio", command, args}` MCP shape.
3. Plan and apply: MCP in `~/.commandcode/mcp.json`, hooks in `~/.commandcode/settings.json`, rules in
   `~/.commandcode/AGENTS.md`.
4. Record the unsupported events in the plan notes, the manifest and `docs/25-installers.md`.
5. Prove merge, backup, second-run idempotence and uninstall in the installer test.

## Acceptance criteria

- [x] Dry run prints three steps and writes nothing.
- [x] Existing `permissions`, other MCP servers and other settings are kept.
- [x] A second install changes nothing.
- [x] Uninstall removes only the `aletheia` server and the `# aletheia-managed` hooks.
- [x] Missing events are stated in the installer output and in `docs/25-installers.md`.
- [x] Hook events captured: `SessionStart` context, `PostToolUse` tool events, `Stop` compression queue.

## Formats and their sources

| Item | Source | Date |
|---|---|---|
| Events: `PreToolUse`, `PostToolUse`, `Stop`, `SessionStart`; `SessionStart.source = startup\|resume\|clear` | Command Code bundled reference `reference/hooks.md` (header: generated from `https://commandcode.ai/docs`) | 2026-10-26 |
| `hooks.<Event>[].{matcher?, hooks: [{type, command, timeout?}]}` | Same reference, "Settings schema" | 2026-10-26 |
| stdin fields `session_id`, `cwd`, `hook_event_name`, `tool_name`, `tool_display_name`, `tool_input`, `tool_response` | Same reference, "Hook input" | 2026-10-26 |
| stdout `hookSpecificOutput.additionalContext` for SessionStart | Same reference, "Hook output" | 2026-10-26 |
| `~/.commandcode/mcp.json` and `{transport: "stdio", command, args}` | Bundled `reference/mcp.md` and the real `~/.commandcode/mcp.json` | 2026-10-26 |

`https://commandcode.ai/docs/hooks` returned HTTP 502 when fetched on 2026-10-26. `cmd --version` on this machine
reported 1.88.0. The real `~/.commandcode/settings.json` had `permissions` and no `hooks`, which is why the test
pre-creates settings to prove the merge.
