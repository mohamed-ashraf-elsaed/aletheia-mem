## Goal

Show the owner's repeated goals in the Work tab. Goals come only from typed prompt rows, never from tool output,
agent text or summaries. The first pass is rule-based and needs no model.

## Files to touch

- `src/hub/goals.mjs`
- `src/hub/routes.mjs`
- `public/work-view.js`
- `public/tabs/work.js`
- `test/work-goals.test.mjs`
- `test/work-views.test.mjs`

## What changed

- `proposeGoals(store, {project})` reads `memories.kind = 'prompt'` only. It extracts an imperative verb and the
  first two content words of the object ("add retry button", "fix login"). A topic becomes a goal only when it
  appears in at least two different sessions.
- Each goal carries `count` (quotes), `sessionCount`, `firstSeen`, `lastSeen`, the projects and dated quotes with
  memory ids. The id is a stable 16-hex hash of scope + topic.
- `goalAction(store, id, {action})` supports `pin`, `unpin`, `dismiss` and `restore`; they write the
  `work.goals.pinned` / `work.goals.dismissed` settings and an audit row. No memory or prompt is deleted.
- `GET /v1/work/goals` and `POST /api/hub/goals/:id` expose the list and the four actions.
- The Work tab shows the goals with count and last-seen date, a dated-quote details block, Pin/Unpin and Dismiss,
  plus a dismissed-goals details block with Restore.
- Tool events, summaries and non-imperative notes were asserted absent from the quotes.

## Acceptance criteria

- [x] Only prompt rows are read; tool and summary text never becomes a goal.
- [x] A topic repeated in two sessions is shown with its quote count and dated ids.
- [x] A topic in one session is not shown for that project; it can appear when all projects are combined.
- [x] Pin and dismiss are reversible settings; no row is deleted.
- [x] The route lists, dismisses and restores.
