# T-067: Add MCP Streamable HTTP transport

Status: validated
Phase: P3
Depends on: T-011
Validated on: 2026-10-26
Evidence: see the Validation section below.

## Goal

Serve MCP over HTTP on loopback with Origin validation and optional bearer auth.

## Why

D1 F-I03. See [20-claude-mem-feature-matrix.md](../20-claude-mem-feature-matrix.md) and, where relevant,
[22-improve-the-numbers.md](../22-improve-the-numbers.md) or [23-memory-building.md](../23-memory-building.md).

## Files to touch

- `src/hub/mcp-http.mjs` (new): the Streamable HTTP endpoint handler.
- `src/server.mjs`: mounts `/mcp` with the optional API key.
- `src/hub/mcp.mjs`: passes an optional `projects` scope through `callTool` (used by the remote endpoint in
  T-107); unchanged behaviour when no scope is set.
- `test/mcp-http.test.mjs` (new): the validation test.

## Steps

1. Implement the Streamable HTTP endpoints.
2. Validate Origin and Host to block rebinding.
3. Reuse the existing API key.
4. Test with the official SDK client.

Deviation, 2026-10-26: the official MCP SDK client was not installed. The repository allows zero npm
dependencies, and `@modelcontextprotocol/sdk` would be a new one. The transport is exercised with raw `fetch`
(including the `Accept` header, `Mcp-Session-Id`, batches and the 202/405 answers), which is what the SDK
would send. The spec details come from the official specification:
https://modelcontextprotocol.io/specification/2025-03-26/basic/transports, fetched 2026-10-26
(also in docs/tasks/research-log.md).

## Acceptance criteria

- [x] initialize and tools/list complete over the HTTP transport (raw fetch; the SDK client itself was not
  installed because no npm dependency is allowed — see the deviation above).
- [x] A wrong Origin is rejected.
- [x] A missing key is rejected when configured.
