# T-006: Publish an OpenAPI document generated from the routes

Status: validated
Phase: P0
Depends on: T-005
Validated on: 2026-10-27
Evidence:

## Goal

Produce `docs/openapi.json` that matches the contract tests, and a checker that fails when the file and the tests disagree.

## Why

D1 F-I06. See [20-claude-mem-feature-matrix.md](../20-claude-mem-feature-matrix.md) and, where relevant,
[22-improve-the-numbers.md](../22-improve-the-numbers.md) or [23-memory-building.md](../23-memory-building.md).

## Files to touch

- `docs/openapi.json`
- `scripts/check-openapi.mjs`
- `test/routes-contract.test.mjs`

## Steps

1. Describe each route, method, parameters and response schema.
2. Add `scripts/check-openapi.mjs` that walks the test manifest and the OpenAPI paths.
3. Add `check:openapi` to package.json.

## Acceptance criteria

- [x] Every path in the contract tests is in OpenAPI.
- [x] The checker exits 1 on a missing path.

## Validation command

```bash
bun scripts/check-openapi.mjs
```

Expected: openapi ok: <n> paths

## Evidence

```
$ bun scripts/check-openapi.mjs --write
openapi: wrote 62 route entries to docs/openapi.json

$ bun scripts/check-openapi.mjs
openapi ok: 62 paths
```

Deviation, 2026-10-27: the manifest lives in `test/route-manifest.mjs` (shared with T-005), so the checker imports
that instead of re-listing routes in `test/routes-contract.test.mjs`. `check:openapi` was added to package.json.
