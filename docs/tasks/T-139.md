# T-139: Add UI tests for the one page

Status: validated
Phase: P6
Depends on: T-134, T-135, T-136, T-137, T-138
Validated on: 2026-10-26
Evidence: see below.

## Goal

A server on a random port with a temp data dir; fetch `/` and assert the four tab containers and both scripts
exist; assert every `/v1` route the UI calls exists and returns JSON with the shape the UI reads; assert `/hub`
redirects. Also a DOM-free unit test of the router and render helpers, exported as plain functions.

## Why

The one UI is the product surface. Without a contract test the shell, the routes and the helpers can drift apart
without a failing test. Part A of the `feat/one-ui` work order.

## Files to touch

- `test/one-ui.test.mjs` (new).
- `public/ui-core.js` is imported by the test, which is why the router and view models live in a DOM-free module.

## Acceptance criteria

- [x] `/` returns the shell with `tab-work`, `tab-memory`, `tab-rules`, `tab-tools`, `#root` and both scripts.
- [x] `/hub` returns a 200 redirect page carrying `/#/memory`; `/hub/app.js` still answers.
- [x] `/v1/health` and `/v1/search` answer with the fields the UI reads, and every hub JSON route the tabs call
      answers 200 JSON.
- [x] The doctor route returns per-tool status with hooks, last capture, spool and commands.
- [x] The router, health, fact, channel, review and duplicate helpers are unit-tested with no DOM.
- [x] The UI source contains no `innerHTML`/`outerHTML`/`insertAdjacentHTML`/`document.write` and transpiles.
