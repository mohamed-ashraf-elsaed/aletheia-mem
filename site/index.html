ἀλήθεια · a-lethe · "un-forgetting"

One memory for every AI coding tool.

Aletheia (aletheia-mem) is a free, local memory and rules hub for Claude Code, Codex CLI, Cursor, Gemini CLI and other AI coding tools. They read and write one SQLite store over MCP, REST or a CLI. Write your rules once and sync them into each tool's own instruction file. Export everything and move on whenever you like.

What it does

A small local server, a CLI and an MCP server over one SQLite file. No account, no telemetry, loopback only.

Memory

Search, filter, pin, edit and delete. Observations, summaries, prompts and notes, with full-text search and optional local embeddings. Hooks capture sessions in Claude Code, Command Code, Codex CLI, Cursor, Gemini CLI and Windsurf.

Rules, written once

Sync one rule set into CLAUDE.md, AGENTS.md, GEMINI.md, Cursor, Windsurf, Copilot and Aider files. A managed block, so your own text is never touched. Preview and backup first.

Connect tools

Detect installed tools and write the MCP config for each, with a preview and a backup before any write.

Easy to leave

Export a versioned bundle or Markdown. Import a bundle, or import from claude-mem (read-only, repeatable). Importing twice does not duplicate.

Private by default

Secrets and <private> blocks are removed before anything is stored. Optional LLM features are off until you choose a provider.

A dashboard in plain words

Home shows, per project, what Aletheia knows, which rules apply and which tools are connected, with hints and examples. Activity, Knowledge, Rules and Connections go deeper.

Quick start

Needs Bun 1.1 or newer. No runtime dependencies.

npm install -g aletheia-mem
aletheia-server                       # http://127.0.0.1:37790
aletheia install claude-code          # dry run: prints every file it would change
aletheia install claude-code --write  # MCP entry, hooks and rules block, with backups
aletheia save "Deploys need Node 20.19.6" --project my-app --pin
aletheia search "node version"
aletheia rules add "Run the tests before saying a task is done"
aletheia import claude-mem            # optional: bring claude-mem memory in (read-only)

FAQ

What is Aletheia?

Aletheia (npm package aletheia-mem) is a free, local memory and rules hub for AI coding tools. Hooks in tools such as Claude Code capture what happened, secrets are removed, and one SQLite file on your machine keeps it. Any tool reads it over MCP, REST or a command line.

How do I give Claude Code persistent memory with Aletheia?

Install the package, start the server, then run aletheia install claude-code --write. That writes the MCP server entry, the hooks and the rules block. Hooks have run in real Claude Code sessions over two days of use, one user on one machine.

Is it really free?

Yes. Apache-2.0, no account, no hosted tier, no telemetry. Optional LLM features call the model you configure, and only then.

How is it different from claude-mem?

Both are open source. claude-mem is much larger, with more features and a far bigger community. Aletheia is smaller and tool-neutral: one store for any tool, rules sync to each tool's instruction file, and import from claude-mem.

Does it replace claude-mem?

No. It runs beside it on its own port and never writes to claude-mem's database.

Where is my data?

In ~/.aletheia/hub.db on your machine. Nothing leaves it unless you turn on an LLM provider or share an export.

Can Claude Code, Codex and Cursor share one memory?

Yes, by design: they all read the same local store through MCP, REST or the CLI. Real-tool checks so far cover Claude Code, Command Code and Codex CLI on one machine; Cursor, Gemini CLI and Windsurf are config written from docs, not tested on a real install.

Does it work with my tool?

If your tool speaks MCP or reads an instruction file, probably. Configs are written from documentation and fixture-tested. Only some have been tested on a real install; the tools table on this page says which.
