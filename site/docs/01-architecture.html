1. Architecture

What the original is

claude-mem is a memory plugin for coding agents. Its worker (scripts/worker-service.cjs, a 4.2 MB Bun bundle) records every prompt, tool call, observation and session summary into ~/.claude-mem/claude-mem.db, and serves several web pages. "My Work" is the page at /: a React single-page app (Vite build in ui/work-view/) over a small JSON and server-sent-events API.

The worker listens on 37700 + (uid % 100). That is why this machine's instance is on 37700 (uid 1000). The default 37777 appears only in help text.

Everything the page shows comes from three places:

The page never calls anything else for its main view. It downloads one JSON document, the snapshot, and then keeps it fresh over one event stream.

One snapshot, step by step

WorkViewService.snapshot() (called per request and per poll):

  1. SourceReader.read() computes cheap signatures: work-state head (count, max id, overlay head), activity head (max id and count of five tables, PRAGMA data_version), ledger file mtimes. If none changed, it returns the cached view.
  2. If they changed, inside one read transaction it re-folds work state (when that changed), runs readActivityRows (bounded SQL), builds the agent view, and hashes every raw row each request cites.
  3. goalLinks() attaches, to each request, the goals the alignment step linked it to.
  4. The service adds, per request, a content fingerprint and the review state (checked or not).
  5. HumanCopy.observe() annotates each request with humanCopy and queues generation if a provider is configured.
  6. It adds rulesFile (path, approved count, loaded flag), setup, and the composite revision "<agentRevision>:<digest of reviews>:<humanCopy revision>".

The event stream sends a full snapshot on connect and again whenever revision, source.connected, source.error or setup change. A heartbeat every 15 s carries {at, source}.

Why a clone and not the original

The original is wired into the worker: its routes, its database manager, its cloud sync and its onboarding. The clone keeps the contract and replaces the wiring:

  • It never writes to claude-mem.db. Entries the original appends there (rules, "agent finished", saved goals) go to the clone's own overlay.db, folded in with the source entries.
  • It has no account, cloud sync, or onboarding. /api/setup/state always reports complete.
  • The refresh gives the model its evidence inline and needs no tools, so any chat model works.

Process model

One Bun process. Timers: change poll (only while a page is open), heartbeat (same), human-copy pump (1 s), refresh check (10 min). The refresh runs inside the same process and shells out to python3 (goal export and save) and to the claude CLI when that provider is chosen. A refresh is single-flight: refresh.json records state: running and the pid, and another process refuses to start while that pid lives.
