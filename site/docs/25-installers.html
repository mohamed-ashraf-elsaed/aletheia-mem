One command

aletheia install claude-code --write
aletheia install command-code --write

Without --write the command is a dry run: it prints every step and changes nothing. aletheia uninstall <tool> --write removes only the entries the install manifest lists. Every changed file gets a copy named <file>.aletheia-bak-<timestamp>.

The manifest is <data dir>/install-manifest.json. The default data dir is ~/.aletheia.

What Command Code cannot capture. It has no UserPromptSubmit hook, no SessionEnd hook, and its SessionStart source is startup | resume | clear with no compact. Prompts and session-end summaries are therefore not captured there. The installer prints this, and the install manifest records it. Do not claim otherwise in the README.

The hook command

Each entry runs:

<bun> <data dir>/aletheia.bundle.mjs hook <tool> <event> # aletheia-managed

The absolute Bun path avoids a PATH lookup. The trailing comment is the marker used by uninstall and doctor. apply builds the bundle with Bun's built-in bundler; if that fails it points the hooks at bin/aletheia.mjs instead. The bundle exists because a hook has a ~100 ms budget: loading a dozen modules costs more than the work.

Hook runtime guarantees

  • Exit code is always 0. Broken JSON, an unknown event, a missing store or an internal error never blocks the host.
  • No network call and no model call. Compression is queued, not run in the hook.
  • Text is redacted before it is stored (src/hub/redact.mjs). <private> blocks are dropped.
  • If the database cannot be opened, the already-redacted item is appended to <data dir>/spool/hook-spool.jsonl. The next successful hook flushes the spool.
  • Recalled context is wrapped in <aletheia-memory> with a line saying it is data, not instructions.
  • The entry point has a 150 ms watchdog and always returns.

Rule hygiene

aletheia rules lint [--dir path] [--tools a,b] [--json] checks the store and the managed blocks before a sync. It reports duplicate rules once per group, direct always/never contradictions with the same scope and condition, a rule over 300 characters, an enabled set over 4,000 characters, instructions that ignore safety (ignore previous instructions, bypass security, rm -rf /, ...), and text that matches the redaction patterns (a secret). For every managed block that exists under the project directory or the user home it compares the parsed bullets with the enabled store rules: a rule only in the file and a rule only in the store are both drift, each with the file and line or the rule id. Each finding has a fix hint.

The check is a warning, not a gate: rules sync still runs. --json returns {findings, checked}. A file without the managed-block markers is skipped, so a user's own CLAUDE.md/AGENTS.md text is never compared.

Transcript watcher

Tools without hooks can still be imported from their session files. aletheia watch polls the three verified layouts, keeps a byte offset and turn counter per file in ~/.aletheia/watcher.db, and imports only new lines:

aletheia watch --once
aletheia watch --interval 1000 --batch 50 --tool claude-code,command-code,codex
ToolFolderVerified from
Claude Code~/.claude/projects/<slug>/<session>.jsonlT-121, 2026-10-26
Command Code~/.commandcode/projects/<slug>/<session>.jsonlT-121, 2026-10-26
Codex CLI~/.codex/sessions/<year>/<month>/<day>/rollout-*.jsonltwo real rollouts on this machine, 2026-10-26

The source files are opened read-only. A file that shrinks is re-read from zero. A line without a newline is left for the next pass. A JSON line the parser does not recognise, and a line that is not JSON, are stored as a kind = "raw" episode instead of being dropped. The polling loop is clamped to at least 1000 ms, takes a batch size per file, and the CLI sets nice 10. Restarting resumes at the stored offset; a re-read is deduped by source_ref and content hash.
