6. Frontend

Aletheia has one app page at /. It is plain HTML, CSS and JavaScript: no framework, no build step, no font file, no CDN and no dependency. It works offline. The older claude-mem viewer is kept as an optional page; it is described at the end of this file.

6.2 Pages and the URL

The address is the state. #/memory/facts?status=history&page=3&limit=50 opens the Facts page, History, page 3, 50 rows per page. Back, Forward and reload return to the same place. Changing only a page number or a filter does not rebuild the page.

6.3 Every list is paged on the server

Each list route takes limit (default 25, hard maximum 100) and offset, orders by a unique id so pages never overlap, and answers total, limit, offset and hasMore. The UI sends the page size you pick (10, 25, 50 or 100).

6.4 The four states of every region

region() shows exactly one of: a skeleton shaped like the final layout (the height is held, so nothing jumps), the content, an empty state that says what it means and gives the command or button to fix it, or an error with Retry and Copy details. A background refresh keeps the content on screen; a failed refresh shows a notice beside it. A late answer from an older request is ignored. Buttons that call the API show a spinner, disable, then a check or the error.

Pin, Dismiss, Restore, Accept, Reject, Keep both and Turn off change the screen first and show an Undo for 8 seconds; a failed request rolls the screen back and says why. Merging rows, revoking a device or a link, and writing files into your tools ask first and say what will happen.

6.5 The status bar

Nine indicators (server, database, search index, vectors, embedding model, queue, extractor, last capture, sync) plus Live or Polling. Each is a dot and a short label. Hover, focus or click opens a popover with the details and the exact command to fix it. Sources: /v1/health, /v1/work, /api/hub/sync/status and /api/hub/overview. A source that has not answered is shown as "checking", never as fine.

The bar polls every 10 s, or every 30 s while the /v1/live WebSocket is connected, doubles the wait after each failure up to 60 s, and stops while the page is hidden. A change frame triggers one light refresh and is passed to other views as an aletheia:frame event (the Work tab listens to it). When the server cannot be reached a banner slides in with a countdown and Retry now; the tab icon turns red.

6.6 Keyboard

Ctrl+K or ⌘K the command palette, / the search box, g then w, m, r or t to switch tab, [ and ] for the previous and next page of a list, ? the shortcut sheet, Esc closes a dialog. Shortcuts never fire while you type in a field or while a dialog is open. Tabs, switches and the pager also answer the arrow keys.

6.7 Accessibility, motion and security

  • Contrast is computed from the tokens and tested (WCAG AA, 4.5:1 for text, 3:1 for control edges). Every control has a name, every list row title has a heading, user text carries dir="auto", toasts and status changes are polite live regions, targets are 40 px.
  • Motion uses CSS transitions and the Web Animations API on transform and opacity, with duration tokens of 120, 200 and 320 ms. Under prefers-reduced-motion: reduce movement becomes a short fade. Only loading marks and live status loop, and they pause when the tab is hidden.
  • The app page is served with Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self'; object-src 'none'; base-uri 'none'; form-action 'self'; frame-ancestors 'self'. No innerHTML is used with data, there is no inline handler, and nothing loads from another origin.
  • Secrets are redacted by the server before they reach the page.

6.9 Requests, goals, story and economics

The Work tab is built around requests now, not a flat session list. Each request card shows its status, its progress and the ids behind that progress, an ETA only when one can be measured (otherwise the reason there is none), and what came out of it: commits, pull requests and branches, each with the evidence id and a link to its session page. The filter (all, needs you, shipped), sort (newest, needs you, most progress) and group (by tool) controls refetch GET /v1/work/requests; the route has no offset, so the page size is the only paging control. Dismiss is optimistic and Undo restores; dismissed requests sit in their own folded list. #/work/request/<id> reads GET /v1/work/requests/:id and shows "where this came from": every session with its dated prompts and facts, and a link back to the T-145 session page.

The Goals section is the T-168 roll-up: a status per goal (Moving, Stalled, Nothing on it), aggregate progress with the request count, the linked requests, the merged artifacts, and the open asks split into being worked and nothing working. Requests that serve no goal are counted and linked. Pin, Unpin, Dismiss and Restore still use POST /api/hub/goals/:id.

Below it, the Build story shows shipped, working, waiting and idle counts, the weekly shipping line, the average days to ship (or "n/a") and the corrections that repeat in the owner's own prompts, with dated quotes. Memory gains an Economics page for the T-170 data: the totals strip, the documented read-token counter, and one row per context memory. A per-observation work token value is null by design, so the row prints "n/a" with the response's own sentence; zero is never substituted.

Every value that is a chosen rule rather than a measurement carries an "estimated" link to tasks/unverified.md: request grouping, progress, ETA, goal progress, rule strength bands and read tokens.

6.10 The classic viewer (optional)

public/work.html and public/assets/ are the original claude-mem viewer, kept byte for byte and linked from Tools only when the old database exists. Everything below describes that page, not the Aletheia app.

What it is

public/ is the original's production build, copied unchanged from claude-mem/15.2.0/ui/work-view/: index.html, assets/index-s8vzksbN.js (798 KB, React + Vite, minified, no source map), assets/index-C6x466ZD.css, a lazily loaded setup-page-*.js chunk, fonts (Geist, Hanken Grotesk), three images, favicon.png (was favicon.svg until 2026-10-27), icons.svg. The clone serves these byte for byte. The decision not to rewrite the UI is deliberate: the original source is not shipped, the bundle is Apache-2.0, and it already speaks the API in 03-http-api.md.

Known gaps in the clone

  • /viewer and /tv (other pages of the original) are not provided. The header link 404s.
  • Anything in the setup chunk beyond its first screen.
  • The header shows a "Star" button with a star count. Whether it fetches the count from GitHub at runtime was not checked; if it does, that is the original's behaviour and it needs internet access.

Replacing the classic UI

To write your own front end, you need only: one JSON snapshot, one event stream, four POSTs. Use GET /api/work-view as a typed contract (the key list is asserted in test/server.test.mjs) and keep the fingerprint round trip: send the fingerprint you rendered when reviewing, and re-render from the returned snapshot after any 409.
