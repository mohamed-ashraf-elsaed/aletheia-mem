14. Research: how to build a better AI memory

Date of research: 2026-10-25. Sources are linked. Each claim is tagged [primary] (I read the paper's abstract or page), [secondary] (a summary of it) or [vendor] (a company reporting on its own product). Where two sources disagree I say so.

14.1 How to read this

The field has three kinds of evidence: academic papers with released benchmarks, vendor blog posts that report their own scores, and independent re-runs. The first is the most reliable; the second is the most abundant; the third shows the second cannot be trusted at face value (14.3). This document therefore keeps design findings (which hold across sources) separate from leaderboard numbers (which do not), and adds our own measurements (14.6) because nothing else is comparable.

14.2 Findings that shape the design

#FindingSourceConsequence for this project
1Chat assistants and long-context models lose roughly 30% accuracy on sustained interactions; on LongMemEval-S (about 115k tokens per question) long-context models drop 30 to 60%. Five abilities matter: information extraction, multi-session reasoning, temporal reasoning, knowledge updates, abstention. 500 questions; S ≈ 115k tokens, M ≈ 500 sessions (≈ 1.5M tokens).LongMemEval, arXiv 2410.10813 [primary]Memory is needed; "stuff it all in context" is not the answer. Evaluate all five abilities, not only lookup.
2Index at round level, not whole session; compressing everything into facts alone hurts overall but helps multi-session reasoning.same [primary]Episodes are single turns or tool steps (built). Facts are extra keys, not replacements.
3Fact-augmented key expansion (extracted facts added to the index): recall@k +9.4%, accuracy +5.4% on average.same [primary]Built as a store feature; we measured +8.4 points Recall@5 on LoCoMo using the dataset's facts (14.6). Extraction itself is still to build (E2-1).
4Time-aware query expansion: index events by date, filter by range: temporal recall +6.8% to +11.3%, only with a strong LLM producing the time range.same [primary]Planned, behind an optional model call (E1-6). A cheap rule-based parser handles most cases; Hindsight uses rules first, a small T5 model for the rest.
5A strong recall pipeline = parallel semantic + BM25 + graph + temporal channels, reciprocal rank fusion (k=60), **cross-encoder rerank (cross-encoder/ms-marco-MiniLM-L-6-v2)**, then add memories in reranked order until the token budget is full.Hindsight, arXiv 2512.12818 (full text) [primary]Our pipeline is the same shape and uses the same reranker model (built: BM25, dense, RRF, rerank; planned: graph, temporal, packer).
6Retain extracts "2 to 5 comprehensive facts per conversation", with coreference resolution, temporal normalisation to absolute ranges, participant attribution, entity typing and entity resolution (string similarity + co-occurrence + temporal proximity).same [primary]Spec for E2-1 and E2-2.
7Memory split into four networks: world facts, agent experiences, synthesised entity summaries, evolving beliefs; operations retain / recall / reflect. Reported 39% → 83.6% accuracy over a full-context baseline with the same 20B open model, 91.4% on LongMemEval with a larger backbone, up to 89.61% on LoCoMo (vs 75.78% for the strongest prior open system).same [primary] (abstract numbers)Structure beats raw context, even on a small model. Keep episodes, facts, entity summaries and beliefs separate in the schema (16.3).
8Bi-temporal graph: track when something happened and when it was ingested; a contradicted fact gets an invalid_at, it is not deleted.Zep/Graphiti, arXiv 2501.13956 [primary + secondary]Facts carry valid_from/valid_to and recorded_at (planned, FR-M3).
9Extract, merge and update memories (Mem0); a graph variant adds about 2%; 91% lower p95 latency and over 90% lower token cost than full context.Mem0, arXiv 2504.19413 [primary: abstract; vendor-authored]Token cost savings come from retrieval budgets, not from the memory brand.
10Semantic lossless compression, online consolidation and intent-aware retrieval planning: "average F1 improvement of 26.4% on LoCoMo", "up to 30-fold" fewer tokens (best case).SimpleMem, arXiv 2601.02553 [primary: abstract]Consolidation and intent planning are worth building after retrieval basics (E2-6, E1-6).
11Contextual retrieval: prepend a short generated context to each chunk before embedding and BM25. Failure rate of top-20 retrieval: 5.7% → 3.7% (contextual embeddings), → 2.9% (+ contextual BM25), → 1.9% (+ rerank); about 67% fewer failures.Anthropic, Sept 2024, via Maginative and others [secondary]Same family as fact keys. Cost is a one-time generation pass with prompt caching. Not built.
12Repository context files can hurt. Across SWE-bench tasks and a new 138-issue benchmark, LLM-generated AGENTS.md-style files tended to lower task success and raised inference cost by over 20% (about +2.5 to +3.9 steps per task); human-written files helped most agents slightly; authors advise minimal requirements only.Gloaguen et al., arXiv 2602.11988, ICLR 2026 [secondary: abstract + coverage; numbers unchecked against the paper]The most important finding for a coding-agent memory. Inject less, make it relevant, make rules minimal and human-written, and measure injection against no injection (E5-7). A product that dumps memory into every session may be making agents worse.
13Performance degrades as input grows, even on simple tasks, and distractors that are topically close hurt more (18 models tested).Chroma, Context Rot [secondary summaries; report not read in full]Precision of what is injected matters as much as recall; MMR diversity and abstention are not optional.
14Benchmarks are moving past one million tokens and past lookup: BEAM (100 conversations, 2,000 questions, up to 10M tokens, 10 abilities incl. contradiction resolution, event ordering, instruction following; companion LIGHT with episodic memory, working memory and a scratchpad). MemoryAgentBench: four competencies (accurate retrieval, test-time learning, long-range understanding, conflict resolution / selective forgetting; the name differs between arXiv versions); finds current methods fall short of all four.BEAM, arXiv 2510.27246; MemoryAgentBench, arXiv 2507.05257 [primary/secondary]Target scale: 10M tokens. Include contradiction and forgetting in the eval.
15Serving cost of agentic memory is a research topic of its own ("Total Recall at What Cost?", arXiv 2608.11879)search result title only [not read]Report latency and cost with every accuracy number.

14.4 What the best systems have in common

  1. They do not put all history in the prompt; they retrieve under a token budget.
  2. They keep raw episodes and add derived facts/entities/summaries as extra retrieval keys, with links back.
  3. They fuse keyword and semantic retrieval and often graph and time; the strongest add a cross-encoder rerank.
  4. They treat time as data (valid time and record time), not as text.
  5. They resolve contradictions by invalidation, not overwrite.
  6. They consolidate and forget on a schedule rather than growing without bound.
  7. The ones with real latency numbers are fast because they are local or indexed, not because they are simple.

14.5 Where claude-mem sits (read from its source)

From the repo (11): SQLite plus a Chroma vector service started through uvx chroma-mcp (a Python process), an LLM "observer" that writes observations and summaries, hybrid search, a 3-layer MCP workflow, a large SessionStart context injection with ~15 tuning settings, 208 settings in total, telemetry on by default. Strengths: it ingests meaning (observer observations), it is integrated into many tools, it has a mature UI. Weaknesses visible in this work: search latency of seconds, a second runtime (Python/Chroma) to run, a silent failure that emptied half its My Work view (F1), and default context injection that the AGENTS.md study suggests could cost task success.

F. What the experiments caught (details in 08)

  • My first search scored 0.1%: it required every question word to match (F5).
  • The first claude-mem pilot scored 24.1% because I queried before its index had finished; after it finished, 38.9% (F11). A premature benchmark would have inflated the claimed lead.
  • A latency "optimisation" (aggressive rare-term pruning) was swept against recall: on LoCoMo the settings made no measurable difference (55.0 to 55.1 BM25), so the gentle default (12 terms, 60%) was kept.
  • My rerank benchmark first reported numbers about half the true ones (BM25 29% instead of 56%) because SQLite results went wrong after the cross-encoder ran in the same process (Bun 1.3.10 with onnxruntime). The harness now collects candidates first and reranks afterwards, and it is cross-checked: its non-rerank rows equal a run with no reranker. Numbers from the broken runs were discarded (F12).

G. Threats to validity

LoCoMo is synthetic social chat, not code. Facts come from the dataset. claude-mem is built to ingest through its LLM observer, not raw saves. Single machine, single run per configuration, no confidence intervals (the no-rerank rows were identical across repeated runs, so they are deterministic). The 3-conversation comparison has n = 383.

14.7 Design principles that follow ("optimised" made concrete)

"Optimised 1000%" is not a target; these are the levers, each tied to a measurement above:

  1. Retrieval first, measured. Hybrid + fact keys + rerank, tracked on every commit (E5-9).
  2. Budgeted, minimal injection. Pinned items and rules in a small default block; everything else on demand.
  3. Speed as a feature. Local SQLite and ONNX models; milliseconds, not seconds. Keep the vector scan brute-force until latency says otherwise.
  4. Provenance and time everywhere.
  5. Fail loudly. No silent empty results; probes at import and startup.
  6. Privacy by construction. Redact first, no telemetry, local models supported.
  7. Own the exit. Versioned bundle, Markdown export, rules written back to every tool's own file.
  8. Honest evaluation. Published harness, published baselines, negative results included.

  • The AGENTS.md numbers come from the abstract and press coverage.
  • Context Rot and Anthropic's contextual retrieval were read through secondary coverage, not the original pages.
  • Vendor and third-party benchmark numbers are listed to show disagreement, not as findings.
