21. Competitor landscape

Research date: 2026-10-26. Every star count, licence, language and last-commit date below comes from api.github.com/repos/<owner>/<repo> fetched on that date; every README claim comes from the repository's README fetched the same day. Registry versions come from pypi.org/pypi/<package>/json or api.npmjs.org/downloads/point/last-month/<package>.

Two rules for this document:

  1. Vendor numbers are labelled. A number a project publishes about itself is vendor-claimed, even when it is in a paper. No vendor number is repeated without its conditions, and where conditions are not published the cell says so. Numbers measured by this project are measured-by-us and point at 14.
  2. **UNVERIFIED is a result.** Where a page could not be fetched or a README does not state a fact, the cell says UNVERIFIED and the fetch failure is in research-log.md. Nothing here is filled from memory.

21.1 What counts as a competitor

Included if it does at least one of these: stores memory for AI agents, injects rules/context into coding tools, or exposes a memory server over MCP. Excluded: generic RAG frameworks with no memory abstraction, vector databases, and note-taking apps. The list is deliberately wider than the "usual six" because the coding-agent memory niche now has many small projects with real adoption.

21.3 Benchmark claims, real weaknesses and the concrete counter

claude-memNo benchmark number published on the docs site or README.Needs Python/uv for Chroma; telemetry on by default; 5 hooks must be installed per tool (docs; README).Same data, both systems measured by the same harness: 1.6× Recall@5 raw and ~390× lower idle latency, already measured (14). Keep the harness public and rerun it.
Mem0LoCoMo 92.5, LongMemEval 94.4, 7.0K/6.8K tokens per query, 0.88/1.09 s (README.md, vendor-claimed, no dataset/judge conditions on the page).OSS stack needs a vector store and an LLM; the free path is not one binary (README.md).Beat it where it is not competing: one local SQLite file, rules sync into editor files, no account, no SDK. Publish a like-for-like run only if the same judge and dataset are used.
OpenMemoryNone.99 stars, last commit 2026-07-29; ports sessions but does not publish storage or retrieval details (README.md).One store all tools read, plus a documented export format.
Supermemory"#1 on LoCoMo and LongMemEval"; "95% Recall@15 with 99.4% context reduction"; "99.6% at @10, 99.8% at @5" (README.md, vendor-claimed; dataset split and judge not stated).Claims are not accompanied by a reproduction command on the page fetched; the engine is managed and the self-host path is not a one-liner.Publish raw per-question outputs and the exact command. ZepDMR 94.8% vs MemGPT 93.4% (arXiv:2501.13956 abstract, vendor-authored).Zep itself is a paid cloud; the OSS part is Graphiti, which needs Neo4j/FalkorDB/Neptune plus OpenSearch (README.md).No graph database to install. Add a graph channel later (T-048) without making it a prerequisite.

CogneeREADME links a benchmarks section but the extracted text has no number.Python graph/vector stack; self-hosted but not a single file; Codex plugin is the only hook path (README.md).A single Bun process and SQLite; rules sync to nine editors, not one plugin.
LangMemNone.A library, not a product: no MCP, no capture, no CLI; native store assumes LangGraph (README.md).Ship the whole loop: capture, store, retrieve, rules, migrate, UI.
MemoriBenchmark image links to memorilabs.ai/benchmark; no number in the README text (vendor-claimed).Enterprise-shaped Python infrastructure; no coding-tool hook story beyond OpenClaw.Free local default, no account, honest benchmark with a command.

21.6 What the landscape actually says

Six findings, each visible in the tables above:

  1. Local-first is not a differentiator by itself. At least 20 projects run locally. What is rare is local-first plus rules sync plus a measured retrieval number. Only this repository claims all three, and its answer-accuracy number is still missing.
  2. The coding-tool niche is crowded and converging on the same shape. claude-mem, Engram, agentmemory, claude-mem-lite, MemoryScope/ReMe, OpenViking and Mooncite all combine hooks, SQLite or files, MCP and some extraction. A new project must beat them on a measured axis, not on feature count.
  3. The framework niche is a different market. Mem0, Zep/Graphiti, Letta, Cognee, LangMem, Memori and Mastra sell an SDK to application builders. They are not trying to be the user's cross-tool hub, and they should not be compared on "rules sync".
  4. Benchmarks are not comparable. Mem0 reports 92.5 on LoCoMo; Memvid claims +35% "SOTA"; MemoryOS claims +49 F1; Supermemory claims "#1"; none of the fetched pages states the judge model, the split and the token budget in the same place. The conflict is documented in 14. The only defensible claim is a number produced by a published harness.
  5. The paid line is drawn at sync and teams. Nearly every free core sells cloud sync, team sharing, or managed extraction. That leaves "free, local, self-hosted team sharing" open. It is task T-083, not a current feature.
  6. Two very large projects are adjacent, not competitors. codebase-memory-mcp (47.5k stars) and Context Mode (32.3k) optimise code understanding and context size. They can be used alongside Aletheia; they do not store the decisions Aletheia stores.

21.7 The three niches where a free, tool-neutral, reproducibly benchmarked memory can win

Niche 1: the multi-tool developer who refuses an account. The pain is concrete: four instruction files, three memory systems, none of them shared. Aletheia already writes rules into nine tools' own files and exposes one store over MCP, REST and CLI. The winning claim is not "more features"; it is "one install, no account, your files, your data, and an export you can read". Measured support: rules sync exists (src/hub/rules-sync.mjs), bundle export exists (src/hub/store.mjs:431), and no competitor in table 21.4 does both.

Niche 2: the team that cannot send prompts to a vendor. Cloud sync and TeamBrain are paid everywhere. A self-hosted shared store with per-client keys, an audit log and a review queue is a real gap. Aletheia has the local store and the audit log; it lacks the server mode and ACLs (T-081, T-082). This is the only niche where the competitor's paid boundary is also the technical boundary.

Niche 3: the evaluator who does not believe vendor numbers. Every vendor number in 21.3 is self-reported. A public harness with raw outputs, negative results and a dated run would be unique. Aletheia already publishes retrieval results and the exact commands, including a failed first attempt (14). The missing half is LLM-judged answer accuracy (T-051). Until that exists, the honest claim is "reproducible retrieval benchmark", not "best memory".

What Aletheia should not claim: more tools than claude-mem, better answer accuracy than Mem0 or Zep, graph reasoning, team sync, or Windows support. None is true today.
