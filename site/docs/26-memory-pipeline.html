26. The memory pipeline as built

Status: implemented, 2026-10-26. This page describes the code that exists, not the plan in 23. Where the two differ, this page wins.

Last change: 2026-10-26 (the one UI, dismiss/restore, provider chain, output language and transcript back-fill).

26.1 One page

hook (Claude Code / Command Code)
  → redact + drop <private>                      src/hub/redact.mjs
  → memories row (kind prompt | event | summary)  src/hub/store.mjs
  → compress.queue setting                        src/hub/hooks/shared.mjs
  → hook returns; no model, no network

worker (server background task or `aletheia compress --daemon`)
  → jobs row                                     src/hub/queue.mjs
  → claim one oldest-due job (BEGIN IMMEDIATE)
  → episode per memory row (and any episode written directly, e.g. a back-filled transcript)
  → windows of 20 episodes / 12,000 chars        src/hub/facts.mjs (chunkEpisodes)
  → provider (extract model) or rule extractor
  → strict validator, one retry with the refusal
  → transaction: facts + keys + links + mark the window extracted
  → contradiction check (newer fact closes the older one)
  → usage row (model, mode, tokens, dollars)     src/hub/facts.mjs, src/hub/usage.mjs
  → job done | pending with exponential backoff | failed

search
  → facts_fts and memory_keys_fts (FTS5)
  → current facts by default; history and as-of on request
  → fact hits first, each with its episode; memory hits after

context
  → pinned and recent memories, then the current facts (cold facts are excluded), then the rules

Every stage that can fail is a row or a file, not in-memory state. A kill -9 between windows leaves the job claimable and the completed windows marked, so the restart neither loses nor repeats work.

The memories table is kept, not replaced by a view. That is the one deliberate difference from D4 §23.3: every existing read path and every existing test keeps working, and the additive migration copies rows into the new tables without pretending the old table is gone.

26.3 Modes and providers

  • ALETHEIA_PROVIDER=none (default): no model call. The rule extractor accepts only a plain "subject verb object" sentence, so it stays quiet on tool noise.
  • local: any OpenAI-compatible endpoint on this machine (ALETHEIA_LOCAL_BASE_URL, default http://127.0.0.1:11434/v1/chat/completions). No API key is required; response_format is not sent.
  • openai, openrouter: an OpenAI-compatible endpoint with ALETHEIA_OPENAI_API_KEY.
  • claude-cli: the claude CLI in print mode, no tools.
  • fake: test only. Canned answers from ALETHEIA_FAKE_RESPONSE or ALETHEIA_FAKE_FILE; never the network.

Model routing: ALETHEIA_EXTRACT_MODEL for extraction (the small model) and ALETHEIA_SUMMARY_MODEL for summaries (the larger model). With claude-cli the defaults are haiku and sonnet; with an OpenAI-compatible provider the default is ALETHEIA_OPENAI_MODEL.

Modes live in src/hub/modes/*.json: code, chill, language-en, language-es. ALETHEIA_MODE selects one. The mode adds an instruction to the fact prompt; it never changes the JSON schema.

An ordered provider chain can replace the single provider: ALETHEIA_PROVIDERS=ollama,openrouter,openai builds each preset in order. On a quota, 429, 5xx or timeout the provider is skipped for a cool-down and the next is tried; a 400 is surfaced. Requests are capped at ALETHEIA_MAX_CONCURRENT (1 by default), each has ALETHEIA_PROVIDER_TIMEOUT_MS, and presets exist for Ollama, LM Studio, llama.cpp, OpenAI, OpenRouter and an anthropic-compatible URL (which requires ALETHEIA_ANTHROPIC_BASE_URL; see §26.8).

26.7 What is not built

  • Real-provider extraction quality. The local provider code path is exercised with an injected fetch and the fake provider. Ollama was reachable on this machine on 2026-10-26: a trivial llama3.2:1b chat call returned in 2.9 s, but the facts-v1 request over a 2-turn window returned HTTP 500 after 4 min 41 s. No provider extraction pass completed, so no provider recall number is claimed.
  • Answer accuracy. LoCoMo measures retrieval only. No reader/judge harness has been run (T-051).
  • Graph retrieval. Entities, aliases and fact_entities exist and are written by the extractor; there is no graph traversal channel yet (T-048).
  • Automatic pruning. aletheia prune is still explicit. The worker builds summaries and embeddings; it never prunes. prune --apply is also the only path that deletes a dismissed row.

26.8 UNVERIFIED

  • Fact extraction quality on a real model: the rule extractor was measured on LoCoMo on 2026-10-26 (1,672 facts, Recall@5 57.3% → 57.7%, +0.4 points); the dataset's own facts gave 57.5% → 64.8% (+7.3 points). A real local model's extraction was not completed, so its quality is not measured. See 22 §22.9.
  • A real Ollama endpoint accepting the exact extraction request body: one trivial chat completion succeeded (2.9 s); the facts-v1 request over a 2-turn window returned HTTP 500 after 4 min 41 s, so the exact body is not verified against a real model.
  • Spearman on a human importance ranking: measured only on a synthetic 200-item rank (0.645).
  • Dedupe precision on human-labelled pairs: measured only on a synthetic 200-pair set (precision 1.00, recall 0.90).
  • Contradiction accuracy on the 50-pair knowledge-update set in D4: measured only on a synthetic 30-pair set (30/30).
  • LoCoMo dataset licence and hash are recorded in 22.9; the dataset itself is not committed.
  • The anthropic-compatible provider preset has no default URL. Anthropic publishes no OpenAI-shaped chat endpoint that this project verified, so the preset requires ALETHEIA_ANTHROPIC_BASE_URL and points at a gateway. No gateway was tested. See tasks/unverified.md.
  • The one UI was loaded in Chromium on 2026-10-26 and checked for rendering and console errors (no errors). Its pixel layout at 375 px, and its keyboard-only path, were not captured by an automated assertion.
  • Transcript back-fill supports only Claude Code and Command Code, the two layouts read on this machine. Other tools' session files were not read, so their formats are not supported and not guessed.

26.9 The one UI

One page at /, four hash routes, one shared header:

RouteWhat it showsMain routes it calls
#/workAletheia's own Work view: sessions, review items, current facts, owner goals; #/work/session/<id> is the read-only session page/v1/work, /v1/work/goals, /v1/work/session/:id
#/memorystats, memories, facts (current/history), search, review queue, dismissed, import/export/api/hub/memories, /facts, /review, /dismissed, /v1/search
#/rulesrule editor, suggested rules, sync, import/api/hub/rules, /rule-suggestions
#/toolsread-only installer status from doctor/api/hub/doctor

The Work view was added on 2026-10-26 (T-142 to T-147). src/hub/work.mjs merges the memory and episode views of a session, so a fresh hook capture is visible before extraction and a back-filled transcript is visible without memories. It returns the last typed prompt, the last summary with its source facts, current facts, review items, queue depth, pinned rows, recent dismissals and the last capture per tool. src/hub/goals.mjs derives goals from memories.kind = 'prompt' only (repeated imperative topics across sessions); pin and dismiss are settings, never deletes. The page refreshes every 10 s only while visible. The old viewer remains at /work-view/work.html; the Tools tab links to it only when the old database exists, and NOTICE.md records its Apache-2.0 origin.

The header carries a project selector, a memory search box and a health dot from /v1/health. /hub redirects to /#/memory so old links keep working. public/ui-core.js holds the router and the view helpers with no DOM, which is what test/one-ui.test.mjs imports.

Every hide action is reversible: memories and facts are dismissed and restored; a rule is turned off, not deleted; a review row can be reopened if it was rejected; a dismissed rule suggestion and a kept-apart duplicate pair can be restored. Permanent DELETE /api/hub/memories/:id stays in the API and CLI, not in the page.
