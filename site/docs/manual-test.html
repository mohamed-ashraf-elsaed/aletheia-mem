Manual test: real Claude Code and Command Code sessions

This is the check a person runs once on a real machine. The automated tests use a temporary HOME; they cannot prove that the host tool calls our hooks.

Legend: RUN BY AUTHOR means the command was run on 2026-10-26. NOT RUN BY AUTHOR means it needs a real interactive session and was not run.

0. Prerequisites

  • Bun 1.1 or newer: bun --version.
  • This repository checked out.
  • No server needed. Hooks write to the SQLite store directly. Start bun bin/aletheia-server.mjs only if you want the Hub UI or the MCP server.

1. Preview (safe, writes nothing)

RUN BY AUTHOR

HOME=$(mktemp -d) bun bin/aletheia.mjs install claude-code --dry-run

Expected: three steps (mcp, hooks, rules) and "Dry run: nothing was written."

2. Install into your real HOME

NOT RUN BY AUTHOR

bun bin/aletheia.mjs install claude-code --write
bun bin/aletheia.mjs install command-code --write

Expected: each prints three written files and builds ~/.aletheia/aletheia.bundle.mjs. Check the backups exist:

ls ~/.claude/*.aletheia-bak-* ~/.claude.json.aletheia-bak-* ~/.commandcode/*.aletheia-bak-* 2>/dev/null

Run the install again. Expected: every step says done and "Already installed; nothing changed." No new backups.

3. A real Claude Code session

NOT RUN BY AUTHOR

cd /path/to/a/git/repo
claude

Inside the session:

  1. Ask: What memory or rules do you have for this project? The answer should mention the pinned memory and rules from the SessionStart block. The block starts with <aletheia-memory>.
  2. Submit a normal prompt: Add a short comment to README.md.
  3. Let it run a tool (read or edit the file).
  4. Run /compact, then ask again: What memory do you see now? The context should be injected again.
  5. Exit with /exit.

Then in a shell:

bun bin/aletheia.mjs search "README"
bun bin/aletheia.mjs doctor

Expected:

  • search finds the prompt and the tool event with tool claude-code.
  • doctor prints ok server only if a server is running; ok hooks claude-code must say 5/5; ok spool must say empty; last capture must show a recent time.

4. A real Command Code session

NOT RUN BY AUTHOR

cd /path/to/a/git/repo
cmd

Inside the session:

  1. Ask: What memory do you have for this project? The SessionStart context should be visible.
  2. Ask it to run a shell command, e.g. Run ls and tell me what you see.
  3. End the turn normally.

Then:

bun bin/aletheia.mjs search "ls" --tool command-code
bun bin/aletheia.mjs doctor

Expected:

  • search finds the SHELL: tool event.
  • doctor prints ok hooks command-code with 3/3.
  • Prompts are not captured in Command Code. That is expected: it has no UserPromptSubmit hook.
  • SessionEnd summaries are not captured either.

If a hook does not fire, run cmd --debug and tail -f ~/.commandcode/logs/command.log. For Claude Code, check ~/.claude/settings.json still contains the # aletheia-managed entries.

5. Uninstall

NOT RUN BY AUTHOR

bun bin/aletheia.mjs uninstall claude-code --write
bun bin/aletheia.mjs uninstall command-code --write

Expected: only the # aletheia-managed hooks and the aletheia MCP server are removed. Your own hooks, your other MCP servers, permissions, model and other settings remain. The managed rules block is removed from ~/.claude/CLAUDE.md and ~/.commandcode/AGENTS.md; text outside the markers stays.

A second uninstall prints <tool> ... is not installed.

6. The one UI (Work, Memory, Rules, Tools)

The shell is checked by test/one-ui.test.mjs (routes, tab containers, API shapes, DOM-free helpers). A real Chromium check was also run.

RUN BY AUTHOR, 2026-10-26 with a temporary server and a temporary HOME:

HOME=/tmp/aletheia-ui-home ALETHEIA_DATA_DIR=/tmp/aletheia-ui-data ALETHEIA_PORT=38881 \
  bun bin/aletheia-server.mjs

Opened http://127.0.0.1:38881/#/memory, then #/rules, #/tools and #/work in Chromium through the connected Playwright MCP browser. Observed:

  • The header stayed visible on all four tabs: tab bar, project selector, search box and a green health dot labelled "Server healthy".
  • The Memory tab rendered the stats, memories, facts Current/History toggle, review queue, dismissed rows and both details blocks. No console errors.
  • Typing retry in the header search and pressing Enter kept the #/memory route and printed the channels (facts: lexical + keys, episodes: lexical, fused: none) and the empty-store reason.
  • The Rules tab rendered the editor, suggestions, sync and import panels; no console errors.
  • The Tools tab rendered the installer cards, the hook counts, spool sizes and the full doctor table; no console errors.
  • The Work tab showed Aletheia's own view, not the old iframe: a health/last-capture/queue/mode strip, "Now" with three sessions (one in progress, two finished), "Needs you" with a contradiction, a rule suggestion and a dismissed row, "Recent memory" with source and importance, and a goal with two dated quotes.
  • The session page #/work/session/s1?project=shop showed the summary, an ordered timeline (prompt, tool, prompt, summary) and the extracted fact with its source. No console errors.
  • prefers-color-scheme: dark was emulated; the page stayed readable and the shell colours switched.

NOT RUN BY AUTHOR: a person should still check the Work tab at 375 px width, with a keyboard only (Tab through the header, open each tab, open a details block, pin and restore a goal, expand a truncated prompt with "Show more"), and with a real live capture over more than 10 seconds to see the refresh. At 375 px confirm the page does not scroll horizontally and every button, tab link, select, search box and details summary is at least 40 px tall to tap. The automated run proves the scripts load and the DOM is reachable; it does not assert pixel layout or the timer under a real host.

8. Two-machine sync (NOT RUN BY AUTHOR)

The sync engine is covered by test/sync-core.test.mjs, test/sync-tombstones.test.mjs, test/sync-devices.test.mjs and test/tokens-quotas-audit.test.mjs, all against temporary data dirs and a loopback hub. A real two-machine run has not been done.

NOT RUN BY AUTHOR. To run it by hand, on the hub machine:

bun bin/aletheia-sync.mjs --port 37791 --db ~/.aletheia/sync.db
aletheia sync pair --db ~/.aletheia/sync.db

On the device machine:

aletheia sync join http://<hub-host>:37791 <code> --name laptop
aletheia sync run

Expected: the device lists on the hub (aletheia sync devices), pushes and pulls move ops, and a revoke on the hub makes the device's next call fail. A non-loopback bind must print the TLS warning unless --behind-tls is set.

E2EE on two machines (NOT RUN BY AUTHOR)

The E2EE paths are covered by test/sync-e2ee.test.mjs against temp dirs and a loopback hub; no real two-machine E2EE run has been done.

NOT RUN BY AUTHOR. On the hub machine:

aletheia sync enable-e2ee --passphrase '<passphrase>'
aletheia sync pair
aletheia sync export-recovery-key --out ~/aletheia-recovery.key
ls -l ~/aletheia-recovery.key   # expect -rw------- (0600)

On each device machine:

aletheia sync join <url> <code>
aletheia sync unlock-e2ee --passphrase '<passphrase>'
aletheia sync run

Expected: aletheia sync status shows E2EE on; the server's sync.db has no plaintext titles (the ops show an @e2ee envelope); a wrong passphrase fails cleanly; aletheia sync rotate-key and aletheia sync change-passphrase work; and without the passphrase or the recovery file the data is unreadable.

9. A real client against the remote MCP endpoint (NOT RUN BY AUTHOR)

The endpoint is tested with raw fetch in test/remote-mcp.test.mjs; no real MCP client has connected to it.

NOT RUN BY AUTHOR. To run it by hand, on the hub machine:

bun bin/aletheia-sync.mjs --db ~/.aletheia/sync.db --hub-db ~/.aletheia/hub.db
aletheia mcp-link create --projects shop

Then, on the same machine or a device that can reach the hub over a TLS tunnel:

claude mcp add --transport http aletheia http://127.0.0.1:37791/mcp --header "Authorization: Bearer <token>"

Expected: claude mcp list shows the server connected; a prompt like "search memory for backoff" finds the memory; aletheia audit shows one mcp.call row per tool call; aletheia mcp-link revoke <id> makes the next call fail with 401. For a remote hub the URL must be the tunnel's HTTPS URL and the hub must run with --behind-tls; add --mcp-origins https://claude.ai if a browser-based client is used.

11. Auto-start service (NOT RUN BY AUTHOR)

The generated text is checked by test/service.test.mjs against a temporary HOME. The unit is never enabled and the server is never started by the author.

Linux default unit (~/.config/systemd/user/aletheia.service): Restart=on-failure, Nice=10, loopback only, with CPUQuota/MemoryMax defaults 50% and 1G documented in comments and overridable via aletheia service install --cpu-quota X --memory-max Y --write.

NOT RUN BY AUTHOR. To run it by hand on Linux:

aletheia service install --write
systemctl --user daemon-reload
systemctl --user enable --now aletheia.service

The macOS plist is from-docs-only (Apple launchd docs, fetched 2026-10-26) and is not tested on a real Mac. Windows is not supported.

12. The transcript watcher (NOT RUN BY AUTHOR)

The watcher reads the three verified folders read-only and imports only new lines. test/watcher.test.mjs uses fixture files, not a live host session.

HOME=$(mktemp -d) bun bin/aletheia.mjs watch --once --tool claude-code,command-code,codex
HOME=$(mktemp -d) bun bin/aletheia.mjs watch --interval 1000 --batch 50
  1. Confirm the first pass reports the fixture files and the expected turns; a second pass reports added 0.
  2. Append one line to a transcript file, run watch --once, and confirm only that line is added.
  3. Append a line without a trailing newline; the pass reports partial and adds nothing. Finish the line and the turn is added once.
  4. Append {"type":"future_event"} or a line that is not JSON; it is stored as a raw episode, not dropped.
  5. Check ~/.aletheia/watcher.db has one watch_state row per file and that its offset equals the file size.
  6. Confirm the source files' bytes and mtimes did not change and no file was written under the three folders.
  7. The polling loop runs with nice 10, an interval of at least 1000 ms and the configured batch size.

The Codex layout was read from two real rollouts on this machine (2026-10-26): session_meta carries the id and cwd, response_item/message carries user/assistant text, and developer messages are skipped. No live Claude Code, Command Code or Codex session was watched while it was being written.

13. Requests, goals, story and economics (NOT RUN BY AUTHOR)

test/requests.test.mjs, test/requests-progress.test.mjs, test/artifacts.test.mjs, test/goals-rollup.test.mjs, test/story.test.mjs, test/economics.test.mjs, test/rule-strength.test.mjs, test/rules-decide.test.mjs and test/work-query.test.mjs cover these on a seeded temporary database. No real owner history was used, and the UI is not wired, so this is a backend check only.

NOT RUN BY AUTHOR. With a seeded hub (see test/requests.test.mjs for the seed), start a server on a free loopback port with a temporary HOME and data dir:

HOME=$(mktemp -d) ALETHEIA_DATA_DIR=$(mktemp -d) ALETHEIA_HUB_DB=/tmp/requests.db \
  ALETHEIA_PORT=38883 bun bin/aletheia-server.mjs

From another shell:

curl -s 'http://127.0.0.1:38883/v1/work/requests?project=shop&filter=needs-you&sort=most-progress&group=tool'
curl -s 'http://127.0.0.1:38883/v1/work/goals?project=shop'
curl -s 'http://127.0.0.1:38883/v1/work/story?project=shop'
curl -s 'http://127.0.0.1:38883/v1/context/economics?project=shop'
curl -s 'http://127.0.0.1:38883/api/hub/rule-suggestions?project=shop'

Expected on a seeded store with five requests:

  • counts is {all:5, needsYou:2, shipped:1, working:1, idle:1, waitingOnYou:2, total:5}.
  • The Shipped request has a cameOutOfIt list with a commit, a PR URL and a branch, each with an evidenceId.
  • goals has three goals (two Moving, one Stalled), a noGoal count of 2, and openAsks split into beingWorked and nothingWorking.
  • economics.totals.workTokens is the fact_usage input + output (1500 in the sample) or null with "no usage record"; per-observation workTokens is null with its label.
  • Each rule suggestion carries timesSeen, strength, latestAt and quotes; total/decided/pending are the decision counts.

The CLI prints the same economics JSON:

aletheia context economics --project shop

An empty store returns empty arrays and empty: true on every route. POST /api/hub/rule-suggestions/:id with {"action":"edit","text":"..."} approves the edited text; POST /api/hub/rules/:id/toggle with {"enabled":false} turns a rule off; POST /api/hub/rules/:id/replace sets replacedBy and replacedAtEpoch on the old rule.
