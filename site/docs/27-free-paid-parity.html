Status update, 2026-10-26 (E2EE): T-117 is validated. The optional end-to-end encryption mode for sync is built and the scheme, key hierarchy, rotation, recovery and the exact list of what the server can still see are in 29-sync.md §29.6. E2EE is off by default and per account; unencrypted accounts keep their old behaviour, so "end-to-end encrypted" is only claimed for accounts that enable it.

Status update, 2026-10-26 (remote MCP): T-067 (MCP Streamable HTTP transport) and T-107 (the private remote MCP endpoint) are validated. F8 is built: bearer tokens with an mcp/read scope get the read tools only, project scope and a per-token rate limit apply, every call is audited, and aletheia mcp-link create prints the client config. See 30-remote-mcp.md.

Status update, 2026-10-26 (Hub login): T-110 is validated. F10 is built with one deviation from the A1 design: login exchanges the sync account's admin token for the session cookie (no separate scrypt password, no TOTP yet). Sessions are HttpOnly, SameSite=Strict, Secure-when-HTTPS, expire, and state-changing requests need the CSRF header; failed logins lock out with back-off. Loopback-only servers keep today's behaviour.

Decision

The owner decided on 2026-10-26 that every feature claude-mem, and any rival, sells in a paid tier is built into Aletheia for free, self-hostable, with no account. Earlier documents marked cloud sync, the hosted server, TeamBrain and enterprise controls out-of-scope. Those rows are corrected in 20 and the work is phase P6 in tasks/TASKS.md.

Two limits on this promise, stated now so they are not found later:

  1. Certificates and support contracts cannot be shipped. SOC 2, HIPAA BAAs and SLAs are things a company buys and signs. Aletheia offers the technical parts (local-only data, encryption, deletion, export, audit) and says so plainly.
  2. A feature is "planned" until a test passes. The README and site must not say "supported" for any P6 item before its task is validated.

What is open code and what is not (A1)

  • Open in claude-mem's repo: the sync hub (services/sync-api, Bun plus Postgres), a Cloudflare Worker variant (workers/sync-hub), the hosted Postgres server, and the TeamBrain client. We can read their protocol directly.
  • Not open: the cmem.ai web app (billing, login, dashboard, inference gateway, OAuth MCP server, TeamBrain server). Their behaviour is only known from docs and issues. Whatever A1 marked UNVERIFIED stays unverified.
  • Hosted observation is a normal LLM call. The client points at https://cmem.ai/api/inference/v1 with model cmem-observer. A maintainer said in issue 3763 (2026-09-12) the model is DeepSeek V4 Flash through OpenRouter. We do the same job with a local model or any OpenAI-compatible endpoint.

Build order

  1. Capture and the pipeline finish first (current branch work). Sync needs schema v3 and the queue.
  2. T-102 sync core, then T-103 tombstones and T-104 devices. These three unlock everything else.
  3. T-106 server-side extraction worker and T-109 usage caps (cheap, high value, removes the "uses my agent subscription" problem).
  4. T-107 remote MCP, T-108 tokens and audit, T-110 hub login, then T-111 connectors.
  5. T-112 team mode, then T-113, T-114, T-117.
  6. T-115 enterprise last. The source says these may not exist as products.
