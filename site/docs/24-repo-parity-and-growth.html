24.2.2 File layout and switcher

README.md                          # English is canonical
docs/i18n/README.<code>.md         # one file per language
docs/i18n/.translation-state.json  # source hash per language
scripts/i18n-check.mjs             # drift detector (T-087)

Each translated file starts with:

> Machine-translated from the English README on 2026-10-26. Review welcome: open a PR against this file.
> Source: [README.md](../../README.md)

The switcher line in README.md and in every translated file:

[English](README.md) · [中文](docs/i18n/README.zh.md) · [Español](docs/i18n/README.es.md) · …

For ar, he and ur, add <div dir="rtl"> around the body. Do not machine-translate code blocks, command names, environment variables or URLs.

24.2.3 Workflow

  1. English README changes land first.
  2. A translator (human or machine) updates the target file.
  3. scripts/i18n-check.mjs reads README.md, hashes the translatable text (excluding code fences and the switcher), compares it with .translation-state.json, and exits non-zero for stale languages.
  4. CI runs the check on pull requests that touch README.md or docs/i18n/.
  5. The translated file records the source hash and date. A stale file stays published but is marked stale in the switcher; it is never silently presented as current.
  6. Native-speaker review is recorded in the file header as reviewed by <handle> on <date> only when it happened.

24.2.4 Order of work

  • Wave 1 (T-088): zh, es, pt-br, ja, de, fr, ko, hi, ar, ru. These cover the largest likely audiences and the RTL case.
  • Wave 2 (T-089): the remaining 22.
  • Docs site: translate only the landing page after the README waves. Do not translate 20+ technical documents until the English ones stop changing weekly.

Cost: one machine translation pass per language, then review time. The workflow is cheap; the review is the cost. Do not claim a language is "supported" until its file passes the drift check and at least one human has read it.

24.5.1 What is explicitly out of scope

  • Buying stars, downloads, issues or reviews. GitHub's Acceptable Use Policies prohibit "rank abuse, such as automated starring or following" and "inauthentic interactions, such as fake accounts and automated inauthentic activity" (https://docs.github.com/en/site-policy/acceptable-use-policies/github-acceptable-use-policies, section 4, fetched 2026-10-26).
  • Asking friends to upvote. HN's Show HN guidelines say not to (https://news.ycombinator.com/showhn.html).
  • Copying claude-mem's README text, logo, artwork or screenshots. Apache-2.0 permits code reuse with attribution; it does not make wholesale copying of the project's identity honest or useful. Attribution for the code we did reuse is in NOTICE.md.
  • Paid placement disguised as a recommendation.
  • Badges for things that do not exist. See 24.3.2.

24.5.2 The order that makes sense

  1. Make install real (T-058, T-059): without hooks, a Show HN is a clone-and-read exercise, not a product.
  2. Publish the package (T-080) so "try it" is one command.
  3. Publish answer accuracy (T-051) so the benchmark post is not retrieval-only.
  4. Write the two migration guides, because they are useful regardless of stars.
  5. Submit to the MCP registry and two awesome lists, in that order.
  6. Show HN only when the first three are done.
  7. Translations after the English README stabilises; otherwise every translation is stale in a week.

24.6 What "parity" means for this repository

Parity with claude-mem is not copying its 163 features. It is closing the gaps that make the product usable and the claims checkable:

  • capture without manual calls (three installers, not nine);
  • a measured answer-accuracy number;
  • a reader that can install it in one command;
  • a repository a contributor can navigate (templates, changelog, releases);
  • a reachable README (translations, real badges, a demo).

Everything else in 20 is either out of scope (paid cloud, enterprise) or a differentiator we do not need to match (35 modes, TV view, Grok bot). The 20 highest-value gaps and their tasks are ranked in 20 §20.12.
